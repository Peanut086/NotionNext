# Design System Master File — Journal（手作手账）

**Project:** NotionNext 个人博客主题 `journal`
**Style:** Anti-polish Raw Aesthetic + Sketch Hand-Drawn（ui-ux-pro-max: `anti-polish-raw-aesthetic` / `sketch-hand-drawn-mobile`）
**Generated:** 2026-10-08
**Dials:** Variance 7（有意的不规则）| Motion 2（几乎不动，动的是"纸"）| Density 3（纸张之间要留缝）

> 取代 `design-system/editorial/`。方向已由用户确认：不要常见的极简编辑部风，要一眼不像模板的个人化风格。

---

## 核心概念

整站是一张**被人用胶带和墨水拼出来的纸**。所有"高级感"来自手工瑕疵，而不是来自阴影、渐变或模糊。

三条不可妥协的原则：

1. **全站没有一条直线是笔直的** —— 边框歪斜、笔画出头、元素旋转 ±1.5°
2. **阴影永远是硬偏移** —— `5px 5px 0 ink`，绝不用 `blur`
3. **手写体只负责"说"，印刷体负责"读"** —— 见 Typography 硬约束

## Color

| Role | Hex | Token | 用途 |
|---|---|---|---|
| Paper | `#FDFBF7` | `--paper` | 全站底色，带极淡纸纹 |
| Paper slip | `#FFFFFF` | `--slip` | 文章条/便签底 |
| Ink | `#2D2D2D` | `--ink` | 正文、边框、硬阴影 |
| Ink muted | `#5C5C5C` | `--ink-soft` | 摘要、次要文字 |
| Felt red | `#C81E1E` | `--red` | 邮戳日期、红圈、精选星标、边注。**2026-10-10 由 `#FF4D4D` 整体抬升**（AA 债务清偿，见「纸会老」节末对比度记录；打印节早就在用这个深档）。夜间变体仍是降饱和档 `#D9605F`，不跟降明度 |
| Ballpoint blue | `#2D5DA1` | `--blue` | 链接、手写便条、引用条文字 |
| Sticky yellow | `#FFF9C4` | `--yellow` | 标签胶囊、荧光笔划、关于我便利贴 |
| Tape | `#E8DFCF` @ 70% | `--tape` | 和纸胶带，两端锯齿 |

规则：
- 只有 **3 个彩色**（红/蓝/黄）+ 纸墨两色。加第四色即破坏体系
- 红 = 作者的手在页面上留下的痕迹（标注、圈、戳）；蓝 = 可点击；黄 = 分类与强调
- 文字对比度：`--ink` on `--paper` ≈ 12.6:1；`--ink-soft` on `--paper` ≥ 4.5:1；`--red` / `--blue` 只用于 ≥18px 或粗体，避免小字对比不足

### 深色模式：不做

纸的本体是浅色。`journal` 主题**不提供 dark 变体**，而是在 `DarkModeButton` 存在时提供一张「牛皮纸夜间」变体：`--paper: #2A2622`、`--ink: #EDE6DA`、`--slip: #34302B`，红/蓝/黄整体降饱和 15%。这是降级方案，不是第二主题；若成本过高则在本主题下隐藏切换按钮（需在 `THEME_CONFIG` 声明）。

## Typography（硬约束）

| 层 | Latin | CJK 回退 | 权重/尺寸 | 允许用于 |
|---|---|---|---|---|
| Marker | Amatic SC | — | 700 / 40–64px | 站名 |
| Hand | Kalam | 霞鹜文楷 LXGW WenKai | 700 / 22–30px | 文章标题、区块标题、边注、"关于我"正文便签 |
| Print | Cabin | Noto Sans SC | 400 / **17px / lh 1.9** | **正文、摘要、导航、评论——所有需要读超过 3 行的东西** |
| Stamp | JetBrains Mono | — | 500 / 13px / ls .12em | 日期邮戳、阅读时长、统计数字 |

**Forbidden（出图阶段已踩到）**：不得用手写体排版正文段落。设计稿渲染图里正文是手写的，那是模型的偏差，不是规格。实现时正文必须是 Print 层。

CJK 注意：Amatic/Kalam/Cabin 均无中文字形。手写感的中文用 **LXGW WenKai**（SIL 许可，可自托管），并**只加载 400/700 两档 + 子集化**；静态导出下这是本主题最大的一笔体积，必须走 `font-display: swap` 与本地子集，不允许直连全量 CDN。

> 落地修正（实现时确认）：霞鹜文楷官方比例版**没有 700 档**，最重是 Medium(500)，所以只自托管 **一份 Medium 子集**，在 `@font-face` 里同时映射 400 与 700 两个权重（同一 URL，浏览器只下载一次）。产物 `public/fonts/LXGWWenKai-Medium.subset.woff2`（1.59 MB / 7289 字 = GB2312 一二级 + 拉丁 + 中文标点 + 本站文案），许可随件 `public/fonts/OFL-LXGWWenKai.txt`。族名用 **`'LXGW WenKai Sub'`** 而非 `'LXGW WenKai'`，避免和站点 `FONT_URL` 里那份 CDN 版抢同权重；子集外的字直接回落系统 KaiTi/serif，不引 CDN。重生成：
>
> ```bash
> pyftsubset LXGWWenKai-Medium.ttf --unicodes-file=unicodes.txt \
>   --output-file=public/fonts/LXGWWenKai-Medium.subset.woff2 --flavor=woff2 \
>   --layout-features=kern --no-hinting --desubroutinize --drop-tables+=DSIG \
>   --name-IDs=0,2,3,4,6,13,14 --name-languages=0x409
> ```
>
> `unicodes.txt` = ASCII + Latin-1 + U+3000-303F + U+FF01-FF60 + U+2010-203B + GB2312 区 0xB0-0xF7（用 Python 逐码点解码生成）+ 从渲染页抓出的本站汉字。

> **字体债已清偿（2026-10-10）**：`style.js` 顶部那条 `@import url('https://fonts.googleapis.com/css2?...')` 已经换成六条本地 `@font-face`，Marker/Hand/Print/Stamp 四层的拉丁字形全部自托管在 `public/fonts/`。**主题自己的渲染路径**不再依赖任何外部字体主机。
>
> 但「本主题没有外部字体」这句话是假的，实测要分清两件事：清掉 `@import` 之后首页仍然发出 3 个 `fonts.googleapis.com` 请求，来源是站点 Notion 设置项 `FONT_URL`，它是四条 URL 的数组——elemecdn 那份霞鹜文楷 CSS，加上 `Bitter`、`Noto Sans SC:wght@300`、`Noto Serif SC:wght@300` 三份 Google CSS，由 `components/SEO.js` 的 WebFontLoader 在挂载 1.5s 后异步注入（所以不是首屏渲染阻塞，但 Noto SC 会展开成十几个 gstatic 分片，字节数比这次迁移掉的那条 `@import` 大得多）。**注意本主题的字体栈里 `--font-print` 收在 `'Noto Sans SC'`、`--font-hand` 收在 `'Noto Serif SC'`，这两档今天正是由那份配置提供的**：清 `FONT_URL` 时不必保留它们，清了就是回落到 PingFang/YaHei/系统 KaiTi，符合规格。
>
> 产物（六档共 182 KB，许可随件四个 `OFL-*.txt`）：
>
> | 文件 | 档 | 大小 |
> |---|---|---|
> | `AmaticSC-Bold.subset.woff2` | Marker 700 | 44 KB |
> | `Kalam-Regular.subset.woff2` / `Kalam-Bold.subset.woff2` | Hand 400/700 | 30 KB ×2 |
> | `Cabin-Regular.subset.woff2` / `Cabin-SemiBold.subset.woff2` | Print 400/600 | 22–23 KB |
> | `JetBrainsMono-Medium.subset.woff2` | Stamp 500 | 28 KB |
>
> 三条实现时的决定，改动前请先读：
>
> - **这是迁移不是重排**。族名、权重组合、`font-display: swap` 都与原 `@import` 逐一对齐，包括那个看似多余的 `Cabin 600`——主题里没有任何 `font-weight: 600` 声明，但 Notion 正文的 `<strong>`/`<b>` 走 700，浏览器在同族已加载的档里取最近的那一档，所以 600 实际上就是正文粗体。删掉它正文粗体会落到 Noto Sans SC。
> - **切片范围 = Google 的 `latin` + `latin-ext`，再加代码块会命中的制表符/方块元素/箭头/数学符号/全角 ASCII；相对原 CDN 路径砍掉 Greek、Cyrillic、Devanagari、PUA**（Kalam 原始 TTF 416 KB 里有六成是 Devanagari + PUA，砍掉后 30 KB）。本站没有这些文种，真出现时按字族回退到栈里的下一档，这是刻意接受的偏离。
> - **不再做 `unicode-range` 分片**。Google 那套 23 片是按文种切的，我们只留一档拉丁，分片收益没了；单文件让 `@font-face` 保持六条可读的声明。代价是纯中文页面也会下载这四族——但首页/文章页的邮戳与标记里一定有拉丁数字和字母，实际下载行为没差别。
>
> 取源手法（下次重生成照这个走，别去抓 Google 的 woff2 分片）：用 curl 类 UA 请求 css2，Google 会返回**未切分的静态 TTF**（一个族一个权重一份），现代浏览器 UA 只会拿到按 `unicode-range` 切好的碎片。
>
> ```bash
> curl -A 'curl/8.6.0' 'https://fonts.googleapis.com/css2?family=Kalam:wght@700'   # -> 单个 .ttf
> pyftsubset kalam-700.ttf --output-file=public/fonts/Kalam-Bold.subset.woff2 --flavor=woff2 \
>   --unicodes='<latin + latin-ext + 代码块符号，见上>' --layout-features='*' \
>   --name-IDs=0,1,2,3,4,5,6,7,8,11,13,14 --drop-tables+=DSIG --no-recalc-timestamp
> ```
>
> `--layout-features='*'` 是刻意的：这份工作是去掉外部依赖，不该顺手改变字形行为，手写字体的连字/替代一旦丢了在截图里很难归因。**另注意：Google 静态实例的 `name` 表里 13/14（许可描述/许可 URL）本来就是空的**，只有 0（版权）有值——所以 OFL 的「许可随件」只能靠独立的 `OFL-*.txt` 落实，别指望把许可烧进字体里。
>
> **仍欠的配置债（唯一一条）**：Notion 设置项 `FONT_URL` 那四条外部 CSS（见上一段）。代码侧已无任何引用需要它们，只能去设置页清；清完首页的 `fonts.googleapis.com` 请求应归零，这可以作为验收判据。

## 手工效果的实现配方

| 效果 | 配方 |
|---|---|
| 歪斜边框 | `border: 2px solid var(--ink); border-radius: 255px 15px 225px 15px / 15px 225px 15px 255px;` —— 手绘感的关键，四角不对称 |
| 硬阴影 | `box-shadow: 5px 5px 0 var(--ink)` |
| 元素旋转 | `rotate(-1.2deg)` ~ `rotate(1.2deg)`，同类元素**必须不同值**，用 nth-child 分配固定表，不用随机（避免 hydration 不一致） |
| 和纸胶带 | 独立 `::before` 绝对定位，`background: var(--tape)`，两端 `clip-path: polygon(...)` 做锯齿，`opacity: .75`，可轻微旋转 |
| 撕纸边 | SVG path 或 `mask-image` 撕纸轮廓；引用条与代码块用此形状 |
| 邮戳日期 | 双层边框 + `rotate(-4deg)` + `color: var(--red)` + 轻微 `filter: blur(.2px)` 模拟油墨渗开 |
| 荧光笔划 | `background: linear-gradient(transparent 55%, var(--yellow) 55% 92%, transparent)`，两端不等高 |
| 红圈选中项 | 内联 SVG 椭圆描边（非 `border-radius: 50%`），`stroke: var(--red)` `stroke-width: 2` |
| 纸纹 | 单张 ≤40KB 的平铺 PNG 或 SVG `feTurbulence`，`opacity: .04`，`pointer-events: none` |
| 手写箭头/星星/纸飞机 | 内联 SVG，`stroke-linecap: round`，不用 emoji |

## 状态编码：胶带/图钉是语法，不是装饰（2026-10-09）

之前 `j-tape` / `j-pill-yellow` / 红星是随意分配的，读者看不出任何信息。这一节把它们定成**有来源、有配对、有优先级**的编码。

四条规则：

1. **每个标记必须由真实字段推得**，不允许「列表第一条自动精选」这类假信号（实现时正是这么写的，已废除）
2. **图形不能是唯一表达**（承接无障碍节）：每个状态都要有 Stamp 层文字配对
3. **只用已有材质**：和纸胶带、图钉、折叠角、撕线、便利贴黄。不新增颜色，不新增第四色
4. **数量封顶**：一张纸条最多 3 个状态标记

| 状态 | 数据源（列表阶段可得） | 纸面标记 | Stamp 配对 |
|---|---|---|---|
| 置顶 | `tags.includes(TOP_TAG)`；`TOP_TAG` 走站点配置（`conf/top-tag.config.js`），未配置则此状态恒不出现 | 左上角图钉（内联 SVG，红帽 + 墨线 + 硬偏移 drop-shadow） | 「置顶」 |
| 精选 | `tags.includes(JOURNAL_FEATURED_TAG)`，默认 `featured` | 纸底改便利贴黄 `--yellow` + 标题前红星 | 「精选」 |
| plog 短记 | `tags.includes(JOURNAL_PLOG_TAG)`，与照片墙同一个标签 | 纸底改和纸色 `--tape` + 上沿一条**撕线**（一行铅笔墨点） | 「plog」 |
| 加密 | `post.password` 非空 | 右上角折叠角（`--tape` 三角 + 墨线） | 沿用已有的手写「加密」+ LockDoodle，不再重复出 Stamp |
| 带图 | `pageCoverThumbnail \|\| pageCover` 非空 | 右上角迷你拍立得（白框 + 下沿加宽 + 单色山与太阳线稿） | 「有图」 |
| 已修订 | `lastEditedDate` 比 `publishDate` 晚 **≥ `JOURNAL_REVISED_DAYS`（默认 7）天** | 纸条左下角外侧再斜贴一小块胶带（-34°），表示「另贴过一次」 | 「修订」 |

**冲突与优先级**（写死，不靠运气；截断顺序即数组顺序，见 `stateMarks`）：

- 右上角只有一格：**加密 > 带图**。加密时不出拍立得角标——不给未解锁的内容做任何暗示
- `--tape`（plog）与 `--yellow`（精选）都改纸底：同时命中时取**黄**（精选是作者意图，plog 是体裁），但撕线仍然画
- 「已修订」的小胶带贴在**纸条左下角外侧**，与上沿的主胶带、左上角图钉、右上角标都不争位置；它与一切可叠加
- 超过 3 个时按 加密 > 置顶 > 精选 > 已修订 > plog > 带图 截断

**为什么 plog 用撕线而不是齿孔**：一旦给 `.j-slip` 上 `mask-image` 挖孔，会连带咬掉 `--wobble` 那条歪斜墨边，得不偿失；一行墨点 `repeat-x` 平铺同样是「这里可以撕」。**齿孔/撕线一律用平铺 SVG data URI**（同 `--hand-underline`、`j-footer-rule` 的做法），**禁止用 `radial-gradient` 造孔**——那会引入可见渐变，直接撞反模式。和 `--hand-underline` 一样，`--tear-line` 的颜色写死在 data URI 里，`j-night` 必须再覆盖一次。

**首版截图验收后的两处修正（2026-10-09）**：

- 修订判定原本写「发表与最后编辑不在同一天」，实测本地 8 篇命中 5 篇——Notion 的 `last_edited_time` 改一个标点都会动，密到等于没有信息。改成 **≥ `JOURNAL_REVISED_DAYS` 天**
- 补贴胶带原本斜压在**主胶带之上**（同在上沿），截图里两条胶带看着像随手贴重了，完全读不出「修订」；挪到左下角外侧才成为独立的一格。上沿已经有主胶带 + 图钉 + 角标，**新标记不要再挤上沿**

**作用范围**：角标级的编码只挂在**文章纸条 `PostSlip`** 上（首页 / 分类标签列表 / 搜索 / 标签页 / 404 的「最近还在写」）。归档页是另一种更小的单行载体（一行标题 + 一枚标签 pill），塞角标会挤坏行高——2026-10-10 拍板给它补**轻量文字标记**，口径与实测见下面「归档行：轻量标记」一节；plog 照片墙的拍立得同理——它的体裁本身就是标记。

**实现落点**：判定集中在 `themes/journal/index.js` 的 `stateMarks(post)` 一个函数，`PostSlip` 只消费；总开关 `JOURNAL_STATE_ENCODING`。`JOURNAL_FEATURED_TAG`、`JOURNAL_PLOG_TAG` 是主题标签，`TOP_TAG` 是站点标签——站长只需在 Notion 里打标签，不改代码。

### 归档行：轻量标记（2026-10-10 拍板 · 落地）

原档把归档页登记为「刻意不带编码」，理由是行高。2026-10-10 拍板**推翻的是「那就不标」，不是「角标塞不进单行」**：

| 要素 | 规格 |
|---|---|
| 载体 | **复用 `PostSlip` 已有的 `.j-mark`**（Stamp 层 13px 文字、`--ink-soft`），不新增图形、不新增颜色。图钉 / 折叠角 / 迷你拍立得 / 补贴胶带都是**为整张纸条设计的角标**，放进 19px 标题那一行必然撑破行高——所以这一行只允许用文字 |
| 子集 | **加密 / 修订 / 有图** 三种。判据不是重要性，是**「这一行自己看不看得出来」**：置顶 / 精选 / plog 的数据源是标签，而归档行右端本来就画了 `post.tags[0]` 那枚 pill，同一行里表达两遍只占宽度；加密（点开也要密码）、修订（首发后回来改过）、有图（这篇有配图）从标题和 pill 都读不出来，才是这一行缺的信息 |
| 顺序与封顶 | 仍走 `stateMarks` 的优先级（加密 > 修订 > 有图）与 3 个封顶，总开关 `JOURNAL_STATE_ENCODING` 一并管住——子集是**过滤**，不是第二套判定 |
| 位置 | 标题之后、标签 pill 之前，并与 pill **合成同一个 flex item**（小组 `relative z-[2]`，组内 `gap-x-2`）。标记不可点，所以不需要自己的 z-index——`.j-stretch::after` 那层覆盖层是透明的，压在其下只影响点击不影响可读。**实测分组本身不改变行高**（390 下分组与不分组逐行相同），留它的理由是「`relative z-[2]` 只挂一处」而不是性能 |

**为什么这个子集而不是「最重要的三种」**：实测本地 8 篇的 `stateMarks` 产出是 **有图 6 篇 / 修订 4 篇 / 加密 2 篇**，精选·置顶·plog **0 篇**（站长没打那三个标签）。按重要性取子集的话上线即**整页零标记**，连验收都做不了；按「看不看得出来」取，**今天 8/8 行都带标记**。**判据顺带解决了可验收性**——与红字批注那种「能力先就位、页面上看不见」的情况不同，这一条是能立刻量的。

**顺手记一条量错数据源的样本**：第一版统计写的是「加密 0 篇」，因为我只数了首页 `.j-mark`。而 `PostSlip` 刻意把 `locked` 从 `j-mark` 列表里过滤掉（加密在纸条上走 LockDoodle + 手写「加密」，见上表），所以「没有 j-mark」不等于「没有加密」。归档行这次是**第一次**让「加密」以文字标记出现在列表里。

**成本的真实形态：标记抢的是标题宽度，不是行数**。归档行是 `flex flex-wrap`，标题 `flex-1`；加了标记不会「多出一行」，而是把标题可用的宽度让出去一截，标题于是多折一行。390 实测：标记 + pill 那一组宽 `115–154px`，标题从 `169.9px` 被压到 `143px`。所以验收口径按**逐行高度**算，不看标记个数。

**落地实测（2026-10-10）**：改造前 8 行 = 桌面 `71.6 × 6 / 62.6 × 2`，390 `85.6 / 61.2 / 85.6 / 111.3 / 61.2 / 61.2 / 85.6 / 61.2`。

- **桌面与夜间**：改造后**逐行相同**（`71.6 × 6 / 62.6 × 2`），零成本
- **390 首版（未做减法）**：3 行各长一档、1 行长两档（`136.9`）——失败
- **390 减法后**：`@media (max-width: 767px)` 下 `.j-arch-row` 只留**第一枚**标记（优先级 加密 > 修订 > 有图），8 行变成 `111.3 / 61.2 / 85.6 / 111.3 / 61.2 / 61.2 / 111.3 / 61.2`，即**只剩 2 行各长一档**（`85.6 → 111.3`），其余 6 行与改造前逐行相同
- **残留接受**：再往下减就只能整枚丢掉，而「加密」恰恰是移动端最有用的一枚（点进去才要密码）。规则只挂 `.j-arch-row` 不挂 `.j-days`：首页纸条也住在 `.j-days` 里，那里有宽度，不该跟着减

**实现落点**：子集常量 `ARCHIVE_MARK_KEYS` 与 `stateMarks` 并排放在 `themes/journal/index.js`，归档行 `render` 里过滤；行 class `j-arch-row`；窄屏减法在 `style.js` 第 7 节移动端。护栏见 `__tests__/themes/journalArchiveMarks.test.js`。

## 目录 = 侧伸的索引贴（2026-10-09）

文章页左页边距的目录不再是普通列表，而是**从本子侧面伸出来的索引贴**：每节一张小纸条，左端悬空、右端接进正文纸页，当前那张被翻起来。

| 要素 | 规格 |
|---|---|
| 形状 | 沿用 `--wobble` 歪斜圆角 + 2px 墨边 + **`3px 3px 0` 硬阴影**（小元素，不用 5px 那么重） |
| 颜色 | 贴面**保持纸白**，只有伸出端那一小条色带按 `nth-child` 固定表在 **黄 → 蓝 → 红** 间轮换。**这三色在这里只做定位色，不承载状态语义**——这是全站唯一一处允许三色轮换的地方，别处「红=作者痕迹 / 蓝=可点击 / 黄=分类」的规则不变。不做整张贴填色：`--blue` 上排 `--ink` 文字对比度只有约 2.5:1，会撞无障碍红线 |
| 层级 | 用**伸出量**表达：`indentLevel * 12px` 写进 `--j-ind`，贴面 `margin-left: var(--j-ind)` 且 `max-width: calc(100% - var(--j-ind))`。两条必须成对：只给 margin 不扣 max-width，深层级会顶破 220px 栏宽（实测第 3 张溢出 16px 并触发横向滚动条）。不再叠第二套阶梯，否则层级和顺序会互相读错 |
| 文字 | **Print 层**（Cabin + Noto Sans SC），单行截断。见下方偏离记录。标题自带的 emoji（Notion 里手打的 📝 之类）**不剥离**——正文标题同样带着，目录剥了就对不上 |
| 当前项 | 那张贴**向左抽出 6px** + 阴影增至 `5px 5px 0` + 一道**红色手绘线压在贴面下缘**（复用 `HandRule red`，`preserveAspectRatio: none` 横向拉满，绝对定位 `bottom: 1px`、`rotate(-1.6deg)`、`opacity: .85`）；同时保留 `aria-current='location'`。**不用 `RedCircle`**：它的 SVG 靠 `inset: -8px -14px` 外扩，而目录容器是 `overflow-y-auto`，外扩部分会被裁；贴面文字还要单行截断，圈住一段被截断的文字本身也不成立 |
| hover | 与当前项同一个掀起量（1~2px），**不改布局尺寸**，遵守 Motion 2 |
| 焦点 | 全站统一的 `2px dashed var(--blue)` 虚线轮廓 |
| 旋转 | 每张贴 ±1° 的固定表，仍然 nth-child、无 JS 随机 |

**修掉的一处既有违规**：原实现的索引文字用 `j-hand`（手写体），直接撞 Typography 硬约束里「Print 层负责导航」那一条，且手写体承载了唯一信息。改为 Print 层。

**首版截图验收后的三处修正**：
1. 红线原本居中「划过贴面」，实读为**删除线**（= 这一节作废），语义正好反了。改为压在贴面下缘、带 -1.6° 手抖，读作「翻到这一页时划的记号」。
2. 目录容器 `overflow-y-auto` 会把 `overflow-x` 一并算成 `auto`（CSS 规范：一个轴非 visible 时另一个轴的 visible 按 auto 处理），所以贴面外扩的色带和抽出量都会被裁。给容器加 `pl-3` 留出 12px 余量，实测贴面右缘正好落在栏宽内、`scrollWidth == clientWidth`。
3. 深层级溢出见「层级」行：`max-width` 必须跟着 `--j-ind` 一起减。

**目录缺席时的塌栏（2026-10-09 线上实测）**：`ArticleToc` 在 `post.toc` 为空时 `return null`，而文章页是 `lg:grid-cols-[220px_minmax(0,1fr)]` 的网格、目录占第一格。目录一消失，正文就成了第一个子元素并被**自动定位**进 220px 的边栏列：`/article/plogTest` 实测 `<article>` 只有 220px、`.notion` 被压到 136px，而 `#notion-article` 带 `overflow-hidden`，于是 542px 的图剪在纸外、正文左缘被切。规格定为**正文列一律显式 `lg:col-start-2`**，不依赖自动定位。在线上注入该条复测：恢复 888px / `.notion` 692px，四张图 674/464/674/674 全部落进容器，与有目录的文章几何完全一致。**推论（适用于以后所有栏位）**：凡"某一栏会条件性返回 null"的网格，其余栏必须显式定位；`lock` 分支当初塞一个 `<div />` 占位是同一个坑的另一种凑法，不要照抄。

**未做（登记，不是遗漏）**：响应式规格里写的「移动端目录降级为左下角手绘圆形按钮」目前仍未实现——桌面端 `lg:` 以下整个目录不渲染，与改造前一致。做的时候它是另一个设计稿，不要顺手塞进这一项。

## 一天一摊：日期是纸，不是字段（2026-10-09）

列表里同一天发的文章，原本各占一张纸条、各写一遍日期，读者要自己心算「这三张是同一天」。手账不是这么记的——**一天摊开一页**。所以把「同一天」升级成版式单位：一摊一张纸，纸头一枚大邮戳，纸条贴在纸上。

| 要素 | 规格 |
|---|---|
| 分组键 | `dayKey(post)`（与「状态编码」共用同一个函数），即 `yyyy-MM-dd`。**同天即同一摊**：摊的先后按「该天首次出现在列表里的位置」，摊内保持后端给的顺序。**全局重排按日期排序**是禁止的——后端顺序里置顶在前，按日期一排就把「置顶」和「今天」两套语义搅在一起了。跨年的同月日**不算同一天**，所以键必须带年份 |
| 空白天 | **不补**。没有文章的日期不画空页——画了就是在造「这里本该有内容」的错觉，违反「每个标记必须有真实数据源」 |
| 摊眉 | 一枚大号邮戳（`MM.DD`，沿用 `.j-stamp-date` 的糊边印章感）+ 等宽年份 + 蓝圆珠笔手写星期 + 一篇以上时补一枚等宽计数「2 张」。日期一律**有字**，邮戳图形从不单独承载信息 |
| 单篇摊 | 一张纸、一条摊眉、一张纸条。摊眉与纸条之间 22px，让邮戳落在胶带上方那段空白里 |
| 多篇摊 = 跨页 | 桌面（`md` 起）两栏，中间一道**装订中缝**：`2px dashed var(--ink-soft)`、`opacity .5`，上下各留 18px 不顶到纸边（真本子的线装不穿到边）。中缝是**一个真实元素** `.j-spine`（不是 `::before`——纸条自己的胶带已经占了 `.j-slip::before`），左右两栏按 `ceil(n/2)` 切分。窄屏折回单栏，同一元素转成**横向**一道、落在第 1 与第 2 张之间。**中缝不用 `radial-gradient`、不用 `mask-image`**，虚线一律 `border-style: dashed`，与「撕线」同一套做法 |
| 数量封顶 | **只作用于首页**：一摊最多显示 3 张纸条，第 4 张起折成一行等宽「这天还有 N 张 →」，链到 `/archive#day-YYYY-MM-DD`。首页只有 5 篇的额度，被一天吃掉 4 篇就没了别的日子。**归档不折叠**——归档是全集，折叠等于链到自己 |
| 锚点 | 每摊 `id="day-YYYY-MM-DD"` + `scroll-mt-24`，可被深链；归档页靠它做「这天」的落点 |
| 语义边界 | **跨页 ≠ 精选**，它只说明「同一天发的」。状态语义仍然只归「状态编码」节那六种标记管，两套系统不得互相借用 |
| 层级 | 摊是**纸**，`PostSlip` 是贴在纸上的**纸条**，不合并。摊**不另画纸边或底色**，否则纸中纸；分组感一律由摊眉 + 中缝承担。状态编码只作用于 `PostSlip` 这条规矩不变 |
| 开关 | `JOURNAL_DAY_SPREAD`（默认 true）。关掉即退回逐条列，首页与归档同时退 |

**首版实测的一处修正**：分组原本写成「连续同天才合一摊」（以为列表按日期倒序，扫一遍即可）。实际数据里后端顺序是「置顶优先 + 更新时间」，两篇 2024-06-01 中间被一篇 06-05 隔开，连续分组把它们拆成两摊、还生成两个同名 `id="day-2024-06-01"`。改成按天建 Map、摊序取首次出现位置，才既合了摊又没动后端顺序。

**日期去重**：进了摊之后，纸条自己那枚 `MM.DD` 邮戳就撤掉（首页 `PostSlip` 走 `hideDate`，归档行干脆不渲染日期），日期只在摊眉写一次。原本归档每行重复一遍 `MM.DD` + 月份，同一天两篇就是两行一样的字——**去重是这一项的主要收益**，不只是换个画法。月份挪到摊眉用蓝圆珠笔手写。摊以外的一切（`compact` 列表、文章页「接着读」、404）仍各自带日期，因为那里没有摊眉替它说话。

**未做（登记，不是遗漏）**：跨页两栏刻意做成**等宽**，不做真本子那种左右页宽不等的对开——不等宽要靠 `grid-template-columns` 配一整套断点，而 220px 以下的窄栏里左右差 8px 根本读不出来，先立住「中缝」这一个符号再说。

## 打包细节：连线、抽屉、装订（2026-10-09）

三项都在回答同一个问题：**凭什么这是一摞纸而不是几张独立卡片**。共同点是只表达**已经存在**的关系，不引入新信息。三处一律**不加配置开关**——纯视觉处理、无数据依赖，多三个开关只会让配置面膨胀。

### 上/下一篇之间的铅笔连线

| 要素 | 规格 |
|---|---|
| 触发 | `prev` 与 `next` **同时存在**才画。只有一篇时没有「之间」，画一条断头线就是装饰 |
| 形态 | 两栏之间 56px 空档里一道**波浪虚线 + 一个箭头**：内联 SVG，`stroke-dasharray: 6 5`，箭头那道 path **不**虚线。窄屏整条 `rotate(90deg)` 立在两张纸条当中 |
| 颜色 | **`--ink-soft` 铅笔灰**。不用红（红=作者痕迹/当前项），不用蓝（蓝=可点击，而这条线本身点不动，可点的是两张纸条） |
| 布局 | 桌面三列 `minmax(0,1fr) 56px minmax(0,1fr)`；**只有一篇时退回单列**，别让空着的连线列把纸条挤窄 |
| 修掉的既有违规 | 原来上/下方向**只靠箭头图形**表达，撞「图形不能是唯一表达」。两张纸条各补一枚 Stamp 层等宽小标「上一篇」「下一篇」 |

### 搜索页 = 拉开的抽屉

- 抽屉面板就是那张搜索表单纸条：下沿居中加一只**手绘拉手**（18×10 的 `⊓` 形墨框、`rotate(-1.2deg)`），把「这是一格抽屉」点出来。
- 面板左上角压一张**标签卡**（等宽、纸白墨边、`rotate(-3deg)`），写「关键词 · N 条」。这行信息原本在面板**下面还独立写一遍**，撤掉——一处信息只留一处。
- **抽出**：结果列表 `margin-top: -14px`；抽屉面板 `position: relative` + `z-index: 2`。结果列表**不定位、不加 z-index**——未定位的元素本来就画在定位面板之下，第一排纸条被面板下沿压住，读作从抽屉里抽出来。**不给结果纸条加 transform**，否则和纸条自己的 `--r` 旋转与 hover 掀起打架。
- 空态不画「空抽屉」：没有关键词时结果区整块不渲染，与改造前一致。

### 归档按年装订

- 每年的摊集合进一个 `.j-year-stack`：顶部一道**装订边**（2px 墨线、`rotate(-.4deg)`、只占左侧 92px，像这一摞纸的装订口），边线上压**两枚订书钉**（`⊓` 形墨框，间距 26px，`rotate(-8deg)` / `rotate(6deg)` 固定值、不用随机）。
- 年份邮戳右侧补等宽「N 张」计数（真实数据：该年篇数）。
- 年与年之间间距增至 48px，让「一摞」读得出来。
- **刻意不再加第二道竖向装订线**：归档左侧已经有一条贯穿的时间轴墨线，再画一道就与它打架。装订感只由顶部边 + 两枚钉承担。

### 首版实测撞出的两处既有问题

都不是这一项引入的，是抽屉的「抽出」验收把它们照出来的：

| 问题 | 修正 |
|---|---|
| 结果纸条满屏宽（实测 `x:0 / w:1440`），抽屉面板在壳内（`x:150 / w:1140`），两者左边差 150px，「从抽屉里抽出」完全读不出来 | `PostSlipGrid` 有结果的那条分支没套 `.j-shell`，标签页 / 分类页 / 搜索页一起中招。补一层壳，壳与面板同宽 |
| 挂在 `.j-shell` 上的竖向工具类（`pt-10`、`mt-16`、`py-12`…）**全部静默失效**：搜索页顶部留白实测为 0，标签卡被裁在视口上沿 | `.j-shell` 原本写 `margin: 0 auto; padding: 0 20px` 简写，ID 特异度压过同元素上的 Tailwind 竖向类。改成只锁横向（`margin-left/right: auto`、`padding-left/right: 20px`），竖向留给工具类。**容器类一律不写 margin/padding 简写**，这条对后续新增的壳类同样成立 |

**验收教训**：夜间态必须看**视口截图**（`page.screenshot`），不能用元素截图——元素截图四周的补白按加 `j-night` **之前**的背景合成，会把牛皮纸夜间拍成「暗卡片浮在白纸上」，颜色 token 实测（`--paper: #2a2622`、`rootBg: rgb(42,38,34)`）与画面矛盾即是这个假象。

## 纸会老：按日期的熵（2026-10-09）

一本翻了两年的手账，早先那几页的墨是淡的。这一节把「日期」从字段升级成**材质**：不给旧文章加徽章，而是让它身上的墨自己退。

| 要素 | 规格 |
|---|---|
| 数据源 | `publishDate` 距**今天**的整数天。**基准日一律取 UTC 日编号**（`Math.floor(Date.now() / 86400000)` 减去发布日的 UTC 日编号）：直接用本地时区的 `Date` 差值，服务端与客户端会在跨午夜 / 跨时区时算出不同档位，className 不一致直接撞 hydration |
| 分档 | 三档，**不做连续插值**：`≤ JOURNAL_AGE_MID_DAYS`（默认 180）= 新 → **不加任何类**，与今天完全一致；`≤ JOURNAL_AGE_OLD_DAYS`（默认 730）= 陈；更久 = 旧。连续插值会让每次构建全站纸色微移，diff 噪音且肉眼读不出来 |
| 陈 | 邮戳红 `opacity: .86`。只有这一处 |
| 旧 | 邮戳红 `opacity: .72` + 纸条墨边 `--ink → --ink-soft`（新增 `--j-edge`，默认 `var(--ink)`，全站只有 `.j-slip` 的边框用它） |
| 落点 | `PostSlip` 根节点 + 摊的 `<section class='j-day'>` + 文章页那张 `<article class='j-slip'>`。摊与摊内纸条同一天 → 同一档，不会互相打架 |
| 构建时快照 | 静态导出下 `Date.now()` 是**构建时刻**，纸的年龄冻结到下次构建。所以档位必须粗到「两次构建之间不会跳档」，且老化不承载任何需要精确的信息 |
| 开关 | `JOURNAL_PAPER_AGE`（默认 true）、`JOURNAL_AGE_MID_DAYS`、`JOURNAL_AGE_OLD_DAYS` |

**老化只许碰材质，不许碰语法**（这一节最要紧的一条）：

- **不动底色**。`--slip` 的底色归「状态编码」独占（黄=精选、和纸色=plog）。纸一老就发黄，等于每一张旧纸都在冒充 plog
- **不动胶带**。修订标记就是一小段补贴胶带，材质层一旦给胶带降透明度，旧纸上的「修订」就先被削弱——**状态标记的可读性永远优先于氛围**
- **不动正文、不动硬阴影**。正文对比度是无障碍红线，阴影是结构
- **不引入渐变做旧**（vignette / `radial-gradient` 暗角）、**不贴随机污渍/咖啡渍**。前者撞反模式，后者没有数据源，是纯装饰
- **纸纹不跟着加深**。纸纹是画在 `#theme-journal` 根上的一张平铺 SVG、透明度烧在 data URI 里，要做「越旧越粗」得再存一份更高 alpha 的图，为这点氛围多养一份资源不值

**老化不配 Stamp 文字**：它不是状态，读者不需要「知道」某篇是旧的（日期本来就写在摊眉）。它是材质层，与「索引贴的三色只做定位色」同类。也正因为如此，它必须淡到**不会被误读成一种状态标记**——两档之间只差透明度，不猜新颜色。

**本站数据的实测分布**（2026-10-09）：8 篇 7 个日期，最新一篇 `2025-06-26`（470 天），最旧 `2024-06-01`（860 天）。也就是说**「新」这一档今天是空的**，页面上一半纸落在陈、一半落在旧。这不是阈值选错了——本站确实停更一年多，老化在这一天的正确表现就是「整本都旧了」，等站长再写一篇，新纸自己回到 crisp。

**实测对比度边界（2026-10-10 已清偿）**：邮戳红原档 `#ff4d4d` 落在纸色 `#fdfbf7` 上只有 **3.16**，13px 的 Stamp 小字不达 AA 的 4.5；老化后陈 2.78 / 旧 2.39。修法按当初的结论执行——**整体抬 `--red`**（牵动全站红墨：邮戳、回指箭头、圈选、列表 marker、`j-note` 上的字），新档取 `#c81e1e`，正是「打印」节一直在用的深红，两态从此同 token。实测（headless 浏览器真实渲染，见下）：未老化 **5.55 / 5.74**（纸 / 纸条白底）、陈 **4.62 / 4.76**（达标）、旧 **3.65 / 3.73**。旧档刻意**不单独回调**——那会让「旧」比「新」更醒目，档位语义倒置；单调递减本身就是规格。**夜间未随迁**：`--red` 在 `j-night` 是降饱和档 `#d9605f`（on `#2a2622` 实测 4.14，陈 3.73 / 旧 2.99；落在 `--slip` 夜间纸条上时更低，实测 2.80 / 2.54），本次口径只覆盖亮色；夜间小字未达 AA 登记为新债务，仍不在队列内。

## 红字批注：征用 Notion 的段落颜色（2026-10-09）

「红 = 作者的手在页面上留下的痕迹」是 Color 节的规则，但站长一直没有地方**写**红字：页边批注此前只是设计稿里的画法，没有数据源。这一节补上入口——**从 Notion 里就能用**，不新增块类型、不写自定义语法、不改共享组件。

| 要素 | 规格 |
|---|---|
| 语法 | 在 Notion 里把**整段**文字的颜色设成 Red（段落块右上角 ⋮ → Color → Red）。落到数据是 `block.format.block_color === 'red'`，react-notion-x 渲染成 `<div class="notion-text notion-red …">`（类名构造实测：`cs("notion-text", blockColor && \`notion-${blockColor}\`, blockId)`）。主题只认一条选择器：`.notion-text.notion-red` |
| 为什么是它 | 候选里只有这一条同时满足：Notion 原生、零自定义语法、**整段级**而非行内级（行内彩色走 `text.format.color`，落在 `<span>` 上，不会误触发）、其它主题拿到的是普通红字不坏 |
| 独占 | 这是**征用**：在手账主题里，整段红字从此只等于页边批注，不能再当强调色用。段内局部红字不受影响 |
| 只认段落块 | `.notion-quote` / `.notion-page-link` / `.notion-table-of-contents` 同样带 `blockColor`，但**刻意不接**——引用条和书签卡自己有形状，再叠一层批注语义会互相读错 |

| **不搬进物理页边** | 实测正文测量框 692px、纸页内容宽 804px，中间只剩 112px，塞不进一条能读的批注；靠负 margin 硬推等于把版心写死成魔法数字。所以批注**留在正文流里靠右**，「边注感」由 变窄 + 右贴 + 红 + 手写 + 回指箭头 五件事共同承担，位置只是其中之一 |
| **不旋转** | 「禁止给 `.notion-*` 加 transform」这条在批注上是有代价的：块 DOM 由库生成，主题插不进包装层，所以批注本体**不歪**。歪的只允许是 `::before` 那个装饰伪元素——它不是 `.notion-*` 块，也不参与布局 |
| 夜间 | `--red` 在 `j-night` 里已降饱和，批注自动跟随，不需要额外覆盖 |
| 开关 | **不加**。它不是主题行为，是内容渲染规则，与「表格=方格稿纸」同级，没有「关掉批注」这种配置项 |

**行内彩色一律不改**：Notion 的行内文字颜色（`--notion-red` 那套）是**站长自己的内容选择**，主题把它们统统映射回自己三色，等于拿主题审美覆盖作者意图，还会把「红=作者的手」稀释成「九种颜色都有意义」。所以只征用 `block_color=red` 一条，其余原样透出。

**登记为刻意不做**：`block_color` 其余取值不映射（蓝=可点击已被占用，绿/粉/棕是第四色）。`background_color`（整段底色）**这一条已在 2026-10-10 反转**：原登记的理由是「黄底整段会把划重点从词级抢到段级」，拍板结果是接受段级笔划、只做红底一条，口径与实测见下一节「段落荧光笔划」；其余底色取值仍是不做。

**验收限制（必须先说清）**：站长 Notion 里目前**没有任何红色段落**，这条语法上线即不可见，和 plog 照片墙一样属于「能力先就位」。视觉验收只能靠注入类名（给一个真实 `.notion-text` 加 `notion-red`）验样式；数据通路靠库源码里的类名构造佐证，不是靠线上内容。

### 首版实测撞出的一条内置 !important

批注第一版按 `margin-left: auto` 写，实测**根本没贴到右缘**：窄条左端停在测量框左边（`x:500 / w:292`，右缘本该是 1192），计算值 `marginLeft: 0px`，而同一条规则里的 `width`、`font-size`、`color`、`font-family` 全都生效。逐条枚举命中该元素的规则才看到根因：

> `styles/notion.css` 给 `.notion-text` 写了 `margin: 1px 0 !important`（NotionNext 自带的 Notion 复位表，与 react-notion-x 的 `styles.css` 同时加载）。

`!important` 的 **margin 简写**会一并覆盖 top / right / bottom / left 四条长写，所以主题写在 `.notion-text` 上的任何 margin——那条 `auto`、以及上下 26px / 4px 留白——**全部静默失效**。同档 `!important` 之间才比特异度，选择器再具体也没用，这正是「ID 都压不住」的那种坑。

- **对策**：批注的三条 margin 一律带 `!important`。这是全站唯一一处，理由写死在 `style.js` 的注释里，防止后人当成随手加的。
- **备选已实测但不采用**：`align-self: flex-end` 同样能推到右缘（实测 `x:900 / right:1192`），因为它不是 margin，不挨这一刀；但段落块一旦嵌进 `.notion-text-children`（toggle / 列表子层）父级就不是 flex，`align-self` 会直接失效，而 auto margin 在 block 与 flex 两种父级下都成立。**注意这条理由是 CSS 规范推得的，不是量出来的**——验收页（`/article/adb-install`）里所有 `.notion-text` 都是 `.notion` 的直接子节点，样本里没有嵌套态可测。
- **推论（对后续所有 Notion 块改造成立）**：改 `.notion-text` / `.notion-quote` 这类被 `notion.css` 用 `!important` 锁过的块，先枚举命中规则再判断要不要 `!important`，不要把「声明没生效」误判成「设计不成立」。
- **移动端实测**：390 视口下测量框 314px、窄条 292px（`30ch` 赢了 `100%`），左缩进只剩 21.6px——**手机没有页边，右贴这一件事在窄屏基本读不出来**，批注感由 变窄 / 红 / 手写 / 回指箭头 四件事兜住。不为此单独设移动端宽度档：把窄条压到 `24ch` 只会让边注多出一行，代价大于收益。
- **夜间实测**：`--red` 在 `j-night` 降饱和后，批注文字与回指箭头（data URI 里的 `%23D9605F`）一起跟随，无需额外覆盖。

## 段落荧光笔划：征用 Notion 的段落底色（2026-10-10 拍板 · 落地）

一句话：**作者把整段底色设成红 = 用荧光笔在这一段上划了一道**。入口同样是 Notion 原生属性 —— `block.format.background_color === 'red_background'`，react-notion-x 把取值**原样**拼进类名（`cs("notion-text", blockColor && \`notion-${blockColor}\`, blockId)`），所以主题只认一条选择器：`.notion-text.notion-red_background`。与批注同级：零自定义语法、不新增块类型、不改共享组件。

### 改造前实测：上游给的是一块「第四色」的粉纸

注入类名到验收页 `/article/adb-install`（站长 Notion 里目前没有红底段落，与批注一样属于「能力先就位」）量到的计算值：

| | 计算值 | 文字对比 | 问题 |
|---|---|---|---|
| 日间 | `background-color: rgb(251, 228, 228)`（上游 `--notion-red_background`），文字 `#2d2d2d` | **11.36** | 可读，但整块粉纸是手账三色之外的**第四色**；而且它是「一整块」不是「一道划」——纸片主题里凭空多出一张贴纸 |
| 夜间 | 同一块 `rgb(251, 228, 228)`，**不随 `j-night` 变**；文字 `rgb(237, 230, 218)` | **1.02** | **几乎不可读** |

上游那句 `.notion-red_background { @apply dark:text-black }`（`styles/notion.css:1785`）实测**没有把夜间救回来**：夜间量到的是纸色文字而不是黑。根因不是 Tailwind，是主题自己更早的那条 `#theme-journal .notion-text { color: var(--ink) }` 带 ID、压过了 `.dark` 后代选择器——**别人的兜底规则挡在继承链上，不如自己把颜色写进本规则**。新规则里 `color: var(--ink)` 是显式的，不依赖那条能不能命中。

### 形态：一行一道，而不是一整块

笔划用 `--yellow`，与搜索命中的 `.j-highlight` 同一支笔。但**不能照抄那条声明**：它写的是 `background-size: 100% 62%` + `background-position: 0 78%`，在单行的词级 `<span>` 上成立；换成多行段落，整个块只画**一条**带子，落在末行下缘——「声明生效了、设计却不成立」的又一例。段落要的是**每一行一道**。

- **几何**：`repeating-linear-gradient(180deg, …)` 把「一行一个周期」直接烧进渐变。周期 `1.9em`、带子 `0.563em → 1.741em`，两个数由 `.j-highlight` 现有的 `62%` / `78%` 换算而来（带高 `0.62 × 1.9 = 1.178`；起点 `0.78 × (1 − 0.62) × 1.9 = 0.563`）。em 相对 `font-size`，与行高等比缩放，**换字号不用改数字**，段级划和词级划因此看起来是同一支笔。
- **周期必须等于行高，而行高要在本规则里写死**：`.notion-text` 的 `line-height: 1.9` 目前由 `#theme-journal .notion-text`（`style.js` 正文层那条）给，实测计算值 `32.3px = 17px × 1.9`。带子一旦和行高分家就会逐行累积错位，所以本规则把 `line-height: 1.9` 一并声明——**这不是排版偏好，是几何成立的前提**。
- **`background-origin: content-box`**：`styles/notion.css:789` 给 `.notion-text` 写了 `padding: 3px 2px !important`。默认 `padding-box` 会让第一条带子整体上移 3px 与文字错开，这正是「周期算对了、带子不齐」的根因。`!important` 那条改不动也不必改，换定位基准就够。
- **`background-color: transparent` 要显式清**：上游动的是 `background-color`，我只覆盖 `background-image` 的话粉纸会留在笔划底下。
- **笔划在文字底下，不需要伪元素**：带子涂在该块自己的 background 层，文字是 in-flow content，天然在它上面。因此不和批注的 `::before` 回指箭头抢同一个伪元素——红字 + 红底同时出现时两条规则互不干扰。
- **实测行盒节奏（几何成立与否的唯一判据）**：验收页 7 段里挑了「带行内 code」和「纯文本」两段注入。行盒相对内容框顶部的起点 `6px`，第二段起点 `38.3px`，**间距 32.3px = 周期**，带子实算 `9.571px → 29.597px`（= `0.563em → 1.741em`）。也就是说**行内代码没有撑高行盒**，周期不会逐行漂移——这是当初最担心的失效模式，实测不成立。
- **已知代价：短末行会涂满整幅**。带子是块级背景，段落最后一行只有几个字时，笔划仍一路涂到测量框右缘。真实荧光笔会在文字结束处抬笔，CSS 在块级背景上做不到；唯一的路是把笔划挪到行内元素上，而**纯文本段落的 `.notion-text` 没有可靠的行内子节点**——实测 7 段里 **5 段 `children` 为空**（文字直接挂成 text node），选 `> *` 会让这 5 段完全没有笔划。接受涂满：「整段被划」的语义本来就覆盖到行尾。

### 与搜索命中的关系（拍板时最要紧的取舍）

原档「不映射 `background_color`」登记的理由是怕把划重点从词级抢到段级。2026-10-10 拍板**接受段级笔划**，同物不同源：

- **词级**＝访客搜到的命中，瞬时、可撤销；**段级**＝作者划的，随内容长期存在。
- 区分手段是**范围**（词 vs 整段），不是颜色。刻意**不新增第四色**（不做「红色荧光笔」）——否则「黄＝荧光笔」这条语言就散了，且夜间那个深色档 `#6b6233` 还得再造一个 token。
- 已知代价：作者划过的段落又被搜索命中时，同色两层叠加、命中不太跳。接受——`<mark>` 另有浏览器默认色兜底，且这条语法今天还没有真实内容。

### 夜间 / 打印

- **夜间**：`--yellow` 在 `j-night` 是降饱和档 `#6b6233`，笔划自动跟随。实测纸色文字 `rgb(237, 230, 218)` 压在带子上 **4.95**（AA 达标），对比改造前的 **1.02** —— 这一条同时清偿了粉纸的可读性缺陷。
- **打印**：荧光笔是 `linear-gradient`，纸上不上色，与 `.j-highlight` 归**同一条**降级规则（`background: none` + 蓝色双下划线）。不另设「段落版」的纸上画法：同一个物理对象在纸上只该有一种译法，`text-decoration` 在块级**逐行**画正好接住「一行一道」的语法。

### 仍然刻意不做

- `background_color` 其余取值（gray / blue / green…）**底色本身仍不映射**（作者意图原样透出）。~~登记同类债务~~ **已清偿（2026-10-13）**：夜间可读性按便签翻字修掉，口径与实测见「底色剩余档的夜间可读性」节。
- 只认段落块 `.notion-text`：`.notion-quote`、列表项、callout 的底色不接。除了「它们自己有形状、再叠笔划会读错」，还有一条硬理由——那些块的行高各不相同，`1.9em` 的周期对不上。
- 不加开关：内容渲染规则，与「表格＝方格稿纸」「红字＝批注」同级，没有「关掉荧光笔」这种配置项。

### 验收方式

同批注，注入类名验收（给一个真实 `.notion-text` 加 `notion-red_background`）：量计算值与对比、截图看带子是否**逐行**与文字对齐，并且要含一段带 `.notion-inline-code` 的段落（行内代码是最可能撑高行盒、把后续周期顶歪的东西，验收页 `/article/adb-install` 里就有）。静态护栏写在 `__tests__/themes/journalHighlighter.test.js`：断言周期/带界与 `.j-highlight` 的 `62%`/`78%` 同源、`background-origin: content-box`、`background-color: transparent`、打印段共用同一条降级声明，并反向断言**没有**为段落笔划新增第四色 token。

## 底色剩余档的夜间可读性（2026-10-13 收债落地）

「仍然刻意不做」里登记的债，站长拍板收债时清偿。上游九档纯色底（gray / brown / orange / yellow / green / blue / purple / pink / default）只在浅色态想过：`j-night` 的亮墨字压近白底，**线上 prod 实测 1.00–1.12**（探针在真实页面注入类名只影响本地页面，量的是线上 CSS 的真实命中）。

**口径：便签不褪色，翻的只能是字。**牛皮纸主题里的浅色底块是贴在暗纸上的浅纸片，夜里它还是浅纸片——把底色涂深等于把便签从本子上撕下来涂黑。于是便签内正文转打印态同一支墨 `#2d2d2d`（与打印节同源，不新增 token），实测各档 **10.6–14.3**；便签内链接与行内代码转打印深蓝 `#1e3f73`（实测 8.1–9.4）。行内代码上游是 `.notion-inline-code{color:#eb5757}`——红在便签上还会和「红＝作者的手」撞语义，深蓝一并解决。**底色两态都不动**：日间本来就是深字压浅纸（11+），改底色是越权改作者意图。

**载体只有段落与标题。**fixture 实测（合成块注入 dev 页面量计算值）：`.notion-quote` 的底色被主题 ID 规则改成 `var(--slip)`、`.notion-toggle` 被写死 `transparent`，上游 `class*="_background"` 双双落不了地；callout 走 `_co` 档且被便利贴黄 `!important` 接管。给它们翻字会得到「暗纸配暗字」——所以规则只挂在 `h1/h2/h3` 与 `.notion-text` 上。

**刻意不碰的**：

- `_co` 半透明档：垫在牛皮纸上只剩三成色，实测正文 **4.32–4.66** 本来就可读（gray / yellow 两档差 0.1x 不达 AA，登记不修）。翻字反而会砸到约 2.4。它们内部行内代码的既有低对比也不在本批面内。

## 改于 MM.DD：修订标记的文字注解（2026-10-12 落地）

「已修订」那枚左下角的补贴胶带只说「回来改过」，不说**什么时候改的**。这一节把判定背后的第二个真实时间戳直接写出来：文章页日期行在发表邮戳之后补一枚等宽「改于 MM.DD」。

| 要素 | 规格 |
|---|---|
| 数据源 | `lastEditedDate`。门槛与「状态编码」的修订档**共用同一个函数** `revisedDay(post)`（`JOURNAL_REVISED_DAYS`，默认 7 天）。判定只许有一处，列表与文章页不许各算一遍 |
| 形态 | Stamp 层 13px + `--ink-soft`，跟在发表邮戳与年份之后：`[06.05] 2024 改于 07.02`。**不加红星、不加第二枚胶带**——那是状态层的活，这一行只做陈述 |
| 只出现在文章页 | 列表纸条已由「修订」胶带承载；把日期抄到每张纸条上只是抢宽度，与「归档行轻量标记」的取舍同源 |
| 开关 | **不加**。它是事实陈述不是主题行为；关掉 `JOURNAL_STATE_ENCODING` 只该收起那枚小胶带，不该抹掉「哪天改的」 |
| 夜间 / 打印 | `--ink-soft` 与 Stamp 层两态都已有档，不需要覆盖；打印态 Stamp 本来就是线墨 |

**可见性**：本站 8 篇里 **4 篇命中**，上线当天就能验收——不属于红字批注 / plog 那种「能力先就位」。

**实现落点**：`revisedDay()` 与 `stateMarks()` 并排在 `themes/journal/index.js`，`stateMarks` 改为消费它（原先内联的 `gapDays` 删除）。护栏 `__tests__/themes/journalRevisedDate.test.js`。

## 上次落笔：扉页的诚实状态（2026-10-12 落地）

一本停了一年多的手账，扉页应该老实说它上一次落笔是什么时候。「空白天不补」是同一条原则的另一面——不假装活跃。

| 要素 | 规格 |
|---|---|
| 数据源 | `posts` 里**最大的发表日**（首页本来就拿到全量已发布文章，不另拉数据） |
| 形态 | Masthead 描述行下面一行 Stamp 层：`上次落笔 2025.06.26`；客户端挂载后再补 ` · 停笔 473 天`；当天刚落笔（0 天）不补，「停笔 0 天」是编出来的话 |
| 为什么分两步 | 静态导出下 `Date.now()` 是构建时刻（与「纸会老」的构建期快照同源）。但天数是**日精度**：服务端构建值与水合时的客户端值必然不同，直接渲染会撞 hydration。所以首帧只渲染日期（服务端与客户端首帧逐字符相同），`useEffect` 才把天数补上。**这是渐进增强**：无 JS 与打印态那行日期照样在 |
| 与摊眉的重复风险 | 摊眉已经写了最近一天的 `MM.DD` + 年份。这一行讲的是**整本的状态**，且落在扉页而不是列表区，两处语义不同；措辞刻意用「上次落笔」而不是「最近一天」 |
| 没有发表日 | 整行不渲染，不写「上次落笔 未知」 |
| 开关 | `JOURNAL_LAST_STROKE`（默认 true） |

**刻意不做**：不写「断更」「荒废」这类评价词，只陈述日期与天数。

**实现落点**：`idleDays(key)` 走与「纸会老」同一套 UTC 日编号口径；`Masthead({ lastStrokeKey })`。护栏 `__tests__/themes/journalLastStroke.test.js`（含「首帧不许渲染天数」这条 hydration 护栏）。

## 页码：归档是目录页（2026-10-12 落地）

手账的每一页都有编号，而归档页原本只是「一摞按时间装订的纸」。给它编号，归档立刻读作**目录页**。

| 要素 | 规格 |
|---|---|
| 编号规则 | 全站已发布文章按 **(日期升序, 同日按 slug 字典序)** 排，序号即页码。**tiebreak 用 slug 而不是后端顺序**：后端序是「置顶优先 + 更新时间」，每编辑一次就漂一遍，而印在纸上的页码一漂就全乱——**稳定性优先于与显示顺序一致** |
| 没有发表日 | 不参与编号（本站今天没有这种文章） |
| 格式 | Stamp 层 `P.` + 三位补零（`P.001`），`--ink-soft`，`white-space: nowrap` |
| 出现在哪 | **只有拿得到全量文章的两个地方**：首页纸条（元信息行末尾 `margin-left: auto` 推到右下角，避开已被占满的四个角）与归档行行尾。分类 / 标签 / 搜索 / 404 的列表**刻意不带**——它们的 props 里没有全集，硬算会算出错页码 |
| 文章页 | **刻意不印**。`resolvePostProps` 在把 props 交给主题前就 `delete props.allPages`，文章页拿不到全量列表。要印只能改共享数据层给每篇附加编号字段，与「改动只落在 themes/journal/」的既有边界冲突，登记为**未做的边界**而不是遗漏 |
| 与摊内顺序 | 页码与「一天一摊」的摊内显示顺序**不承诺一致**（tiebreak 不同源）。同日两篇在归档里可能排成 `P.005 / P.003`，这是稳定编号的代价，规格里写死接受 |
| 开关 | `JOURNAL_PAGE_NUMBERS`（默认 true） |

**两处刻意不做（登记，不是遗漏）**：

- **点线引导**（目录页那条 `……`）：归档行的标题本来就是 `flex-1`，再放一条会生长的点线要和标题抢宽度——与「归档行轻量标记」量过的代价同源（真实成本是抢宽度、不是多一行）。第一版只把编号放行尾。
- **卷号 VOL.**：扉页再写一个「第 N 卷」会与页脚既有的 `© 2024–2026 · 第 3 年`（由 `SINCE` 推得）同义重复。同一本子上两个长得很像、口径却不同的计数器，比少一个卷号更糟。

**实现落点**：`pageNumbers(posts)` 返回 `Map<id||slug, n>`，`LayoutIndex` 与 `LayoutArchive` 各自 `useMemo` 算一次后把 `pageNo` 传给渲染；**不许在模块级缓存**（SSR 下会跨请求泄漏）。护栏 `__tests__/themes/journalPageNumbers.test.js`。

## 落笔格：一年的日期点阵（2026-10-12 落地）

设计稿的归档右栏写着「手绘月历（当天红圈圈出）」，**首版从未实现**。这一节把欠账补上，并换成一种更经得起真实数据的画法。

| 要素 | 规格 |
|---|---|
| 数据源 | 全站已发布文章的发表日；按年分块 |
| 日期尺 | 每个月一行 1–31 的尺：刻度用 `repeating-linear-gradient` + `::before`（**不用 `radial-gradient` 造孔**，同「撕线」那条规矩），下缘一道墨线 |
| 墨点 | 落过笔的日子在对应刻度上点一枚 `--ink` 墨点，`left = (day - 0.5) / 31`。一天两篇 → **同一个位点画大点**（`j-cal-dot-2`），不并排画两点 |
| 空白天 / 空白月都不补 | 没落笔的日子没有点，没有落笔的月份没有行——与「空白天不补」同一条原则 |
| 文字配对 | 每月行尾给等宽「N 张」。图形不承载唯一信息：点位讲密度，具体日期仍只在摊眉上写 |
| 颜色 | **不用红**。红是邮戳与作者批注的档位，这一格只是密度，抢红会被读成状态标记 |
| 不给今天画圈 | 设计稿那条「当天红圈」不做。这一格讲**写过的日子**，今天有没有写都落在下一格；而「今天」在静态导出下是构建时刻，圈它等于把一个会漂移的日期做成醒目焦点 |
| 位置 | 归档右栏，「按年份跳转」与「本站统计」之间 |
| 开关 | `JOURNAL_WRITING_GRID`（默认 true） |

**可见性**：8 篇 7 个日期 → 点阵恰好 7 枚点，其中 `2024-06-01` 那枚是大点（两篇）。月份行 6 行 = 2025 的 01/03/04/06 + 2024 的 06/08，行尾「1 / 1 / 1 / 1 / 3 / 1 张」合计 8 张。这条今天就能当场量。

**实现落点**：`yearGrids(posts)` 用**字符串切片**取年月日（不构造 `Date`，避免时区把日期挪一天）；CSS 在 `style.js` 新增的 3i 节（页码 / 落笔格 / 图例共用一节元信息）。护栏 `__tests__/themes/journalWritingGrid.test.js`（含「不许出现 `radial-gradient` 造点」「不新增颜色 token」两条负向断言）。

## 书签：读者留下的铅笔痕（2026-10-12 落地）

前面所有标记的记录者都是站长——Notion 字段、正文颜色、发表日期。这一节是**第一个由读者留下的标记**，所以它顺带定下一条新语法：铅笔灰属于读者。

| 要素 | 规格 |
|---|---|
| 数据源 | 读者自己浏览器里的滚动进度（`localStorage`），**不上传、不进 Notion、不写 cookie**。本站第一次出现「记录者不是站长」的标记 |
| 颜色 | **`--ink-soft` 铅笔灰**，与「铅笔连线」同档。红=作者、蓝=可点、黄=分类，三档已被占满；读者的痕迹只能落到第四档铅笔。**不新增颜色 token** |
| 记录门槛 | 进度 ≥ `JOURNAL_READ_MIN_PCT`（默认 3）才落一条——点开就走不该留痕。同一篇只留**最高**进度，按百分点节流写 |
| 显示 | 文章页：抬头元信息行一枚铅笔小标「上次读到 62%」。列表 / 归档：纸条元信息行同一枚铅笔标，排在页码之前 |
| 首帧纪律 | `useState(null)` + 挂载后 `useEffect` 再读，**SSR 与客户端首帧逐字符相同**。服务端没有 `localStorage`，任何「渲染期读进度」的写法都是崩溃点 |
| 唯一出入口 | 只有 `themes/journal/reading.js` 允许碰 `localStorage`，布局与组件只调它的 `useReadMarks()` / `recordProgress()`。护栏有负向断言：`index.js` 里不许出现 `localStorage` 字样 |
| 上限 | 只留最近 `JOURNAL_READ_KEEP`（默认 200）条，按 `at` 淘汰——读者的历史不该无限长，也不值得无限长 |
| 不自动续读 | **不做「加载后滚到 62%」**。抢读者的滚动位置是冒犯，且与浏览器自带的 scroll restoration 打架。书签只说「上次读到哪儿」，回到那里是读者的手的事 |
| 不做时长 / 字数 | 「读了 4 分 12 秒」要挂秒表、量 DOM 高度，那是给站长看的仪表盘，不是纸上的痕迹 |
| 开关 | `JOURNAL_READING_BOOKMARK`（默认 true）。关掉后既不写也不显示，**存量记录原地不动**——不主动删读者的东西 |

**可见性**：今天 0 条。进度只在读者真读过之后才产生，属于「能力先就位、页面上看不见」那一类，所以图例页对应那行必须把「看不见不是坏了」写明白。本地验收：打开一篇滚到中段，回首页应看到铅笔标。

**实现落点**：`themes/journal/reading.js`（读、写、淘汰、`useReadMarks`）；记录在 `LayoutSlug`，显示在 `PostSlip` 与归档行。护栏 `__tests__/themes/journalBookmark.test.js`（含一条负向断言：`themes/journal/` 里除 `reading.js` 外都不许出现 `localStorage`）。

## 读完的纸打个勾（2026-10-12 落地）

| 要素 | 规格 |
|---|---|
| 判据 | `pct >= JOURNAL_READ_DONE_PCT`（默认 97）即读完。**不是按钮**：打勾的凭据是「你真的滚到了底」，不是「点了一下声称读完了」——与「没有数据源就不画」同一条律 |
| 为什么不做成交互 | 纸条整块本身已是 `<a>`，往里塞 `<button>` 是非法 HTML；而「蓝=可点」这档已经被链接占住。读者的勾必须是铅笔，铅笔不该假装能点 |
| 显示 | 一枚铅笔勾（`--ink-soft` 描边、不对称圆角，同 to_do 那种手绘勾的画法）+ 等宽小字「读完」。与「上次读到 62%」**互斥**：到门槛只留勾，不并排两种进度说法 |
| 纸面 | 打完勾**不把纸条变淡**。已读不是次要——变淡会被读成「这篇不重要」，而它恰恰是读者自己的优先级 |

| 开关 | `JOURNAL_READ_DONE_CHECK`（默认 true）。关掉后**退回「读到 N%」**而不是干脆不显示：读过的痕还是痕，只是没有勾 |

**刻意不做**：不做「标为未读 / 删除单条」的管理面板（那是应用，不是本子）；不做跨设备同步（要账号，而本站的读者不该被要求登录）。

**实现落点**：`reading.js` 的 `isRead(pct)` 是唯一判据，护栏断言 96 / 97 的分界只写在一处；渲染在 `ReadMark`，与 `PageNo` 同排。护栏 `__tests__/themes/journalReadCheck.test.js`。

同语言 OG 卡解决的是「爬虫看到什么」，这一节解决「人转发时手上有什么」。三张卡共用一套纸，只是版式与主角不同。

| 剪报的数据源 | 选中的文字，不是编出来的引号。**没有选区就没有剪报卡这一项**——分享行不许凭空造一句「金句」，那是第一律（每个标记要有真实数据源）最容易被破的地方 |
| 长度上限 | `clampQuote`：压掉换行与控制字符，超 `JOURNAL_CARD_QUOTE_MAX`（默认 160 字）截断加省略号。URL 里塞一整段选区既打不开也难看 |
| 谁决定能不能出卡 | `cardUrl()` 一处判：`EXPORT=true`（静态导出没有 `pages/api`）或 `LINK` 不是绝对 http(s) → 返回 null，分享行**整项不出现**。宁可少一个入口，不给一个点了 404 的链接 |
| 选区采集 | 只认 `#article-wrapper` 里的选区（导航、分享行、评论被框选不该出卡）；`useState(null)` + 挂载后监听 `selectionchange`，首帧没有剪报链（故事链不吃浏览器状态，SSR 就在）——hydration 纪律同「书签」节 |
| 版式差异 | 故事卡把邮戳挪到右下、标题字号升一档、摘要留白变长；剪报卡上沿一道**撕线**（同 plog 短记那排铅笔墨点），引文用 Print 层，出处那行才是标题。同一套 token，**不新增颜色** |
| satori 约束 | 只能吃 CSS 子集：不写 `inline-block`、不用 SVG filter、任何包着元素的分节点都要显式 `display`。jest 渲不出 PNG，所以护栏是「静态 + `renderToStaticMarkup` 验 JSX 结构」，与「同语言 OG 卡」节同例 |
| 刻意不做 | 不做 canvas 下载按钮（右键另存够用）；不做二维码（分享卡是给人看纸的，不是扫码入口）；不做「AI 挑一句」（数据源是编的，违反第一律）；不做多图轮播卡 |
| 开关 | `JOURNAL_SHARE_CARDS`（默认 true，只管故事卡与剪报卡；横卡是 og 元数据，仍归 `JOURNAL_OG_CARD`） |

**可见性**：三型今天都能当场看——本地打开任意文章，「故事卡」随服务端就在（它不吃浏览器状态），再选一句就多出「剪报卡」。线上（非静态导出）同样成立；静态导出下这两个链**整项消失**，这是 `cardUrl()` 的守卫，不是坏了。

**实现落点**：`og-card.js` 的 `OgCard({ size, quote })` + `OG_SIZES` / `clampQuote`；`pages/api/og.js` 只做白名单与透传；`themes/journal/index.js` 把原 `ogImageUrl` 泛化成 `cardUrl(post, params)`，`ShareNote` 加两个链，选区在 `LayoutSlug` 采集后传下来。护栏 `__tests__/themes/journalShareCards.test.js`。

## 往年的今天：归档右栏的时间回声（2026-10-12 落地）

「纸会老」让作者的发表日褪色；这一格反过来——用**读者今天的日期**去旧页里找同月同日的那一篇。它不是推荐位，是同一本日记自己会响一下。

| 要素 | 规格 |
|---|---|
| 落点 | 只在**归档右栏**（`LayoutArchive` 的 `WritingGrid` 之后、本站统计之前）。别处放不了：首页的 `props.posts` 在 `pages/index.js` 里被切成当页 12 张、`allPages` 还被 `delete` 掉——没有全集就没有回声，硬塞等于编数据 |
| 数据源 | 归档 posts 每篇的发表日（`postDate` → `dayKey`），与「纸会老」同源；不新增字段、不读本站之外任何东西 |
| 判定 | `echoYears()`：同月同日**且**年份严格早于今年（`ago > 0`）。今年的那一篇不给自己当回声 |
| 谁的今天 | `localDay()` 取**读者浏览器本地日期**，不是 UTC、不是构建快照。静态生成把「今天」冻在发布那天，那是假回声 |
| 首帧纪律 | `useState(null)` + 挂载后 `setToday(localDay())`：SSR 与 hydration 帧都不渲染这张便条，纪律同「书签」节 |
| 空态 | 没有对上的日子 → **整张便条不出现**。不摆「什么都没有」占位，更不许退化成「随便挑一篇旧文」凑数 |
| 排序与上限 | 按 `ago` 升序（最近的去年排第一），取 `JOURNAL_ON_THIS_DAY_COUNT`（默认 3）篇 |
| 闰年 | 2/29 不往前补到 2/28——补出来的日期是假的，宁可不响 |
| 颜色 | 年份徽章是 `j-stamp j-soft`（`--ink-soft` 铅笔档），标题走 `j-hand` 蓝色可点链。铅笔档 = 读者的痕迹，见「读者侧的铅笔痕」；**不新增 token** |
| 开关 | `JOURNAL_ON_THIS_DAY`（默认 true）、`JOURNAL_ON_THIS_DAY_COUNT`（默认 3）、`JOURNAL_ECHO_TITLE`（默认「往年的今天」） |
| 刻意不做 | 不做全站「历史上的今天」轮播（本站数据只够一张便条）；不做 `/archive/[date]` 日历路由（一张便条撑不起页面）；不加配图（回声是文字的时间差，加图就退化成另一张卡） |

**可见性**：今天（2026-10-12）本站 8 篇里没有对上的日子，右栏就没有这张便条；把时钟拨到 03-26 会看到「1 年前 · Gradle下载超时问题处理办法」。8 篇共 7 个不同的月日，所以一年里它大约亮 7 次——这不是 bug，是小站的真实密度；数据薄的时候便条本来就该经常不在。

**实现落点**：`themes/journal/index.js` 的 `localDay()` / `echoYears()` / `EchoNote`；`echoYears`、`localDay` 导出只为让护栏能直接问判据，站内没有第二个调用方。护栏 `__tests__/themes/journalOnThisDay.test.js`。

## 连载语法：一个标签前缀就是一条线（2026-10-12 落地）

NotionNext 没有 series 概念。这一族用**标签前缀**补上：站长只在 Notion 里打一个标签，代码不动，文章之间就多了一条装订线。与 `JOURNAL_PLOG_TAG`、`JOURNAL_FEATURED_TAG` 同一族做法（征用 Notion 已有字段），区别在于它说的是**篇与篇的关系**，不是某一张纸的状态。

| 要素 | 规格 |
|---|---|
| 语法 | 标签以 `JOURNAL_SERIES_PREFIX`（默认 `连载:`）开头，前缀之后那截就是连载名：`连载:手账入门` → 连载名「手账入门」。**只有前缀、后面没字**（光一个 `连载:`）不算一篇——名字都没有的线不画 |
| 一篇一辑 | 命中多个连载标签时取第一个。不做多辑归属：一篇挂两条线，清单就不知道把它排进哪一列，最后两条线都成噪音 |
| 话数 | 按**发表日升序**、同日按 slug——与「页码」同一把尺。Notion 里没有「第几话」这个字段；让作者手填话数，等于再养一份会漂的真相 |
| 清单落点 | **归档右栏**（`SeriesNote`，在「往年的今天」之后）。口径与它同一条：全集只在归档——文章页的 `resolvePostProps` 里 `delete props.allPages`、首页 posts 被切成当页 12 张、标签页还受分页影响 |
| 文章页给什么 | 只把标签胶囊写成「连载 · 手账入门」，链子仍指回 `/tag/连载:手账入门`。**不做连载内的上/下一篇**：文章页没有全集，算不出来；索引页就是那条线，不是缺功能（**册的入口不在这枚胶囊上**，理由见「连载册」节「入口」行）|
| 不成辑 | 不足 `JOURNAL_SERIES_MIN`（默认 2）话的连载不进清单。一话的「连载」还只是标签，硬列出来是拿语法骗人 |
| 辑序 | 各辑按首话日期降序，最近开辑的排前面 |
| 图例位置 | 进 `LEGEND_SYNTAX`（「其它语法：Notion 里怎么触发」）那一列，**不进 `LEGEND_KEYS`**：连载不是纸上的状态标记，与「一天一摊」「按年装订」同族。OG 卡的 `STATES` 词表因此一字不动 |
| 材质 | 清单行=铅笔灰 `j-stamp j-soft` 的「第 N 话 · MM.DD」+ 手写蓝链（`j-hand`），与「往年的今天」同一格式；胶囊沿用既有黄 pill。**不新增颜色、不新增图形** |
| 纯服务端 | 不读浏览器状态，SSR 首帧就在，与「书签」「往年的今天」正好相反。打印随所在便条（`.j-note` 归零旋转与阴影后照印） |
| 开关 | `JOURNAL_SERIES_PREFIX` 置空即整族关掉（剥前缀只写 `seriesNameOf` 一处）；另有 `JOURNAL_SERIES_LABEL`（胶囊里的词）、`JOURNAL_SERIES_TITLE`（便条标题）、`JOURNAL_SERIES_MIN` |
| 刻意不做 | 不把话数写进标签（`连载:手账入门#3` 那种）：作者填的数会与发表序打架，而清单按它排等于信任一个不校验的输入；不做连载进度条（读者的进度归「书签」节）；**~~不开 `/series/[name]` 新路由（标签页已经是这条线）~~** 已于 2026-10-13 撤销，见下面「连载册 /series/[name]」节——那句话说的是当时的标签页，而它给不出跨页的话数 |

**可见性**：这一项**要打上标签才看得见**（计划里就写明了这条代价）。2026-10-13 之前本站一条 `连载:` 都没有，归档右栏不出清单、胶囊也照原样；当天给 6 篇已发布文章追加了 `连载:Android开发`（4 话）与 `连载:系统架构师`（2 话），清单立刻长出来、胶囊写成「连载 · 名字」且仍链原标签页。图例页「其它语法」里那一行同步补了册子入口的说明。

**实现落点**：`themes/journal/config.js` 四个键；`themes/journal/index.js` 的 `seriesNameOf()` / `seriesOf()` / `tagLabel()` / `seriesGroups()` / `SeriesNote`——剥前缀只有 `seriesNameOf` 一处，`seriesOf`、`seriesGroups`、`tagLabel` 导出只为让护栏能直接问判据。护栏 `__tests__/themes/journalSeries.test.js`。

## 年刊 /year/[year]：把一年印成一册（2026-10-12 落地）

「按年装订」在归档里是倒着找的一摞纸；这一项把它正过来——一年一册，从头翻。册子里**不发明新纸**：摊、邮戳日期、黄标签胶囊、页码 P.0XX、状态标记、便利贴便条全部沿用既有语法。

| 要素 | 规格 |
|---|---|
| 路由登记 | 三处缺一不可：`pages/year/[year].js`、`conf/layout-map.config.js` 的 `'/year/[year]': 'LayoutYearbook'`、`components/SEO.js` 的 `case '/year/[year]'`（`/plog` 那次就漏了第三处） |
| 有哪几册 | **只认 `bookYears()` 一把尺**：它同时决定 `getStaticPaths` 的路径表、右栏「相邻的册」、空册里那句「本站有年份可翻的是」。路由里不许再 `slice(0, 4)` 自己算一遍，否则「链子在、册不在」的 404 迟早出现 |
| 收哪些纸 | `type === 'Post'` 且 `status === 'Published'`，且**有发表日**：`yearOfPost` 走 `dayKey(postDate())`，与「一天一摊」「页码」同一把尺。没有日期的纸进不了任何一册，也不许给它编一个年份 |
| `fallback` | 导出时 `false`（静态产物只可能有真年份），非导出 `'blocking'`——照 `lib/build/staticPaths.js` 的口径 |
| 册内序 | 月份**升序**（1 月在前），归档是降序——册子从头翻，归档倒着找。同月内仍按 `dayGroups` 摊成一天一摊，摊眉只留周几，日期邮戳照旧归每张纸 |
| 页码 | 印**全站**序：`pageNumbers(posts)` 拿的是全集，不按年重置。2024 那册从 P.001 排到 P.004，2025 那册接着 P.005–P.008。年册是从本子里抽出来的活页，不是另立编号的独立成书 |
| 册尾的数 | 六个，且全部手数得出：张数 · 落过笔的月数 · 第一张 MM.DD · 最后一张 MM.DD · 落笔最密的月（某月 ≥2 张才写）· 状态标记（`markCounts` 只列非零项）。**字数 / 阅读时长 / 热度 / PV / 排行一个都不写**：Notion 里没有这些数据，写出来就是拿语法骗人 |
| 空册 | 没纸的年份（如 `/year/2099`）：正文只说「这一册是空的」并列出真正有册的年份，**右栏整列不出现**——零个统计、零个「相邻的册」，摆一张空便条是装饰不是记录 |
| 打印 | `.j-book-month { break-before: page }` 加 `:first-of-type` 归 `auto`：一个月开一页，第一月不留空白页；`.j-book-nav`（相邻的册 +「打印这一册」提示）是屏幕上的导航，纸上不印 |
| 入口 | 归档右栏「按年份跳转」每个年份后面一枚 `年刊 →`（铅笔灰小字章）。**不进顶栏**：顶栏是全站常青的几页，年册逐年增，挂上去等于把导航做成清单。图例页「按年装订」那一行的最后一句也补上了这册从哪翻（护栏钉住） |
| 卷号 | 「页码」节已否决 `VOL.`（与页脚 `© · 第 N 年` 重复）。标题只用「2025 年刊」，不补卷号 |
| 开关 | `JOURNAL_YEARBOOK`（关掉即整页 `return null`，归档那枚入口同关）、`JOURNAL_YEARBOOK_LABEL`（标题那一截，默认「年刊」） |
| 刻意不做 | 不做年度字数 / 最热榜（无源）；不做 `/year` 索引页（归档的年份行就是目录）；不做册内分页（一年几十张纸，翻页是给博客加负担）；不在首页挂「今年这几张」（`resolvePostProps` 之后首页没有全集） |

**可见性**：今天本站 8 篇攒出两册。`/year/2024`：「4 张纸 · 2 个月落过笔」，6 月 · 3 张 → 8 月 · 1 张，页码 P.001–P.004，右栏「第一张 06.01 / 最后一张 08.18 / 落笔最密的月 6 月 · 3 张 / 加密 · 1 张 / 修订 · 4 张 / 有图 · 3 张」，相邻的册只有 `← 2025`。`/year/2025`：「4 张纸 · 4 个月落过笔」（1、3、4、6 月各 1 张），每月都只一张，「落笔最密的月」那一行不出现，页码 P.005–P.008，相邻的册 `2024 →`。`/year/2099` 走空册那条：只说「这一册是空的」，并列出 2025、2024。

**实现落点**：`pages/year/[year].js` 只管取数与切全集；`themes/journal/index.js` 的 `yearOfPost()` / `bookYears()` / `yearMonths()` / `yearStats()` / `usedMarks()` / `LayoutYearbook`；`conf/layout-map.config.js`、`components/SEO.js`、`themes/journal/style.js`（打印）各一处。护栏 `__tests__/themes/journalYearbook.test.js`。

## 连载册 /series/[name]：把一条线印成一辑（2026-10-13）

「连载语法」节当初把 `/series/[name]` 写在「刻意不做」里，理由是「标签页已经是这条线」。**这句理由今天被推翻了**——不是审美变了，是读了标签页的取数代码之后发现，它给不出连载最需要的两样东西：

| 缺口 | 证据 |
|---|---|
| 话数要全集 | `pages/tag/[tag]/index.js` 第 44 行 `delete props.allPages`、第 37–40 行把 `posts` 切到 `POSTS_PER_PAGE`（默认 12）。在标签页里数「第 N 话」只能数**本页**，翻到第二页从 1 重来 |
| 序要发表序 | 标签页继承后端顺序（置顶优先 + 更新时间；见「一天一摊」节那条「列表按日期倒序是错的前提」）。本页内重排解决不了跨页断线 |

补完标签页要动 `pages/tag/[tag]/index.js`，那是全站三十个主题共用的路由——为一个主题的语法改共享层不划算。所以走新路由，并把上面那句「刻意不做」就地划掉。

**一句话规格**：一条连载印成一辑，从第 1 话往下翻。册子里不发明新纸——纸条、话数、页码、状态标记、便利贴便条全部沿用既有语法。

| 要素 | 规格 |
|---|---|
| 路由登记 | 三处缺一不可：`pages/series/[name].js`、`conf/layout-map.config.js` 的 `'/series/[name]': 'LayoutSeries'`、`components/SEO.js` 的 `case '/series/[name]'` |
| 参数形态 | `[name]` 是**已剥前缀**的那截（`/series/手账入门`，不是 `/series/连载:手账入门`）：冒号编码成 `%3A` 既难看也没法念。Next 给 `params.name` 解好码，匹配时直接用连载名 |
| 名字里带 `/` | 这种标签**不进册**（`/series/a/b` 会被路由切成两段，永远匹配不上），仍留在标签页那条线里。在册表里滤掉而不是转义——转义出来的 URL 不是人打的字 |
| 有哪几辑 | **只认 `seriesBooks()` 一把尺**：它就是 `seriesGroups()` 换一层壳（同样的 ≥`JOURNAL_SERIES_MIN`、同样的发表序）。路由表、归档那枚入口、空态里「本站攒得起的册」三处都问它，不许任何一处自己算一遍 |
| 无日期的一话 | 沿用「连载语法」节已钉的护栏：**占一话、日期写 `--.--`、排在最前**。与年册「没日期不进册」刻意不一致——年册的成员由日期决定，辑的成员由标签决定；把一篇从它自己所属的辑里删掉是藏纸，不是诚实 |
| 册内序 | 升序，第 1 话在前（同一把尺：发表日升序、同日按 slug）。册头写「共 N 话」 |
| 页码 | 印**全站**序：`pageNumbers(posts)` 拿的是全集，与年册同理，不在册内重排名次 |
| 册头的数 | 话数 · 首话 MM.DD · 末话 MM.DD · 跨了几个年份。**字数 / 阅读时长 / 热度 / PV / 排行一个都不写**：本站没有可信来源，写出来就是拿语法骗人 |
| 材质 | 一话一张纸 = `PostSlip`；整册左侧一道铅笔竖线（`.j-series-thread` 的 `border-left: 2px dashed var(--ink-soft)`），每行左列 `j-stamp j-soft` 的「第 N 话」。**不新增颜色、不新增图形**；文章页上/下一篇的铅笔连线 `ThreadLink` 仍只服务那一个语义，册内不复用（同一图形两种语义 = 噪音） |
| 入口 | **只有归档右栏 `SeriesNote` 每辑那一行**多一枚 `连载册 →`（铅笔灰小字章，与年册入口同格式）。**文章页的胶囊不改**：`resolvePostProps` 删了 `allPages`，文章页判不出「这一辑成不成辑」，链过去可能是一册空壳——这是本项开工前口头方案的一处改判，原方案想让胶囊分叉 |

**LayoutSlug（文章页）**：左页边距列**侧伸的索引贴目录**（当前项抽出 + 下缘红斜线，见「目录 = 侧伸的索引贴」节）→ 胶带固定的纸页正文 → 邮戳日期 + 黄标签 → 手写大标题 + 出头横线 → **Print 层正文 62ch** → 撕纸条引用（蓝字手写）→ 深色剪纸块代码块（剪刀"复制"）→ 页边红字批注（Notion 段落整段设红即触发；纸页本身按「纸会老」褪色）→ 手绘短横作列表符号 → 荧光笔强调句 → 虚线分隔 → 两张胶带纸条上/下一篇（等宽小标「上一篇」「下一篇」，两篇俱在时中间一道铅笔虚线连线）→ 手写"评论"。

**读者侧的铅笔痕**：文章页抬头与首页纸条上的「上次读到 62%」「读完」由读者自己浏览器里的滚动进度补上，规则见「书签：读者留下的铅笔痕」「读完的纸打个勾」两节。它们只在挂载后出现——SSR 首帧没有它，打印也没有它。

**LayoutArchive（归档）**：手写"归档" + 纸堆涂鸦 + 等宽总数计数条 → 左侧一条歪斜墨线时间轴带手绘节点 → **按年装订**：年份作红色邮戳印章（`rotate(-4deg)`、微糊）+ 等宽「N 张」，该年的摊集顶部一道装订边压两枚订书钉 → 年内按「一天一摊」分组：摊眉一枚大邮戳 + 蓝圆珠笔"六月 · 2 张"，同天多篇作跨页带装订中缝，行内不再重复日期 → 文章作小胶带纸条（标题 Hand 20px + 黄标签）→ 右栏便利贴「按年份跳转」+ 手绘月历（当天红圈圈出）。

### 图片：拍立得的宽度上限必须是相对值（2026-10-09 线上实测）

规格表里「图片 = 拍立得」落地时写成 `#theme-journal .notion-asset-wrapper-image { max-width: 560px }`，
把 react-notion-x 那条 `max-width: 100%` 顶掉了（同元素上带 ID 的规则特异度更高）。结果是这张纸只有
一个**绝对**上限，和栏宽彻底脱钩：

- 桌面 692px 正文栏：560 ≤ 692，看不出问题
- 手机 390 视口：正文框实测 314px，拍立得仍按 560px 排（块内层是 `<div style="width:1200px">`，
  被自己的 `max-width:100%` 收到 542），实测 `figure` 落在 `x=-85 / w=560`，左右各溢出 85px，
  被 `#notion-article` 的 `overflow-hidden` 剪掉 —— 照片两头直接消失，而且不产生横向滚动条，所以纯看滚动是发现不了的
- 再叠上「目录缺席时的塌栏」那一条，同一篇文章在桌面上溢出得更狠

改成 `max-width: min(560px, 100%)`：**上限仍然是「不许贴满整页宽」的 560，但永远不越过纸的右边界**。
`100%` 的基准是 `.notion-page-content` 的内容盒，正是纸的可用宽。

**但只改 `max-width` 不够——上游还有一条 `min-width: 100%` 在压着它。** CSS 的求解顺序里
`min-width` 赢过 `max-width`，所以 1100 视口实测：正文栏 692 时拍立得 `figure` 宽 **692**、
里面的照片 464，**560 这个上限在桌面端从来没有生效过**，画面变成"一张小照片泡在大白卡纸里"，
加厚下沿离照片还留着 200 多 px 的空。补 `min-width: 0` 之后实测 `figure` 收到 560（窄图 482），
白边四周一圈、下沿 26px 紧贴照片，才是规格说的「拍立得框」。

**这条的通用结论**：给 react-notion-x 的块加外框时，`max-width` 单独写是无效声明，必须连同
`min-width` 一起接管；判断依据不是"看起来差不多"，而是量 `figure` 与内部 `img` 两个宽度是否相等
（差值只应等于边框 + 内边距）。

**推论（凡是用 `#theme-journal` 覆盖上游 `max-width: 100%` 的地方都适用）**：绝对值只能作为 `min()`
的一项，不能顶替 `100%`。同理，给 Notion 块加外框时若顺手写了 `border-bottom-width`、`padding`，
要意识到这些都会从可用宽里扣掉，照片的实际显示宽是 `min(上限, 栏宽) - 边框 - 内边距`。

### plog 落地记录（2026-10-08，实现时的偏离与结论）

- **数据源不是 `type === 'PAGE'` 集合**。本仓库 `allPages` 的 `type` 只有 `Post` / `Page`，而 `Page` 是「关于 / 友链」这类固定页，不是照片。实际实现取**标签**：带 `JOURNAL_PLOG_TAG`（默认 `plog`，可用 `NEXT_PUBLIC_JOURNAL_PLOG_TAG` 覆盖）的已发布文章，**一篇 = 一张拍立得**，一句话说明用文章标题，日期用文章日期（逐张不同，正是出图里全 09.28 的那个瑕疵在真实数据下天然不存在）。
- 照片取 `pageCoverThumbnail || pageCover`；两者都空时渲染 `.j-photo-empty` + `PhotoLineArt`（山 + 太阳的单色线稿），不给灰块。
- **筛选放在主题里**，`pages/plog/index.js` 只负责给出全部已发布文章。原因：主题的 `CONFIG` 在 `getStaticProps` 阶段读不到（`siteConfig` 只合并 `blog.config.js` + Notion 配置），把标签名写进路由就要在两处重复默认值；这样改标签也无需重新构建。
- 路由是静态段 `/plog`，优先级高于 `/[prefix]`。若将来在 Notion 里建了 slug 为 `plog` 的页面，会被这个路由遮蔽。
- 拼贴墙的旋转与不等间距靠 `.j-collage` 的 `5n` 静态表（-2.4°~+2.8° + 逐档 `margin-top`），仍是 nth-child、无 JS 随机。
- 为此给 `.j-polaroid` 补了 `position: relative`：条目标题用 `.j-stretch`（`::after { inset: 0 }`）把整张拍立得变成可点区，需要定位父级，否则伪元素会贴到更外层。同时补上与纸条一致的 hover「掀起 1px」。
- 空态不是灰块，是一张胶带纸条：蓝圆珠笔「这一页还没贴照片。」+ Print 层说明怎么加标签。

## 打印（@media print）（2026-10-10 落地）

一个手作纸主题最该被打印——**但主题的材质几乎全靠 `background` 和 `box-shadow` 成立，而浏览器默认不打印背景**。
所以打印不是"少点装饰"，是一次**语法翻译**：凡是印不出来的，要么主动清掉（胶带：留着只占位），要么换成线（方格稿纸 → 真边框）。
一句话规则：**纸上只剩线**——歪斜墨框、邮戳描边、铅笔虚线、装订订书钉。

实现全在 `themes/journal/style.js` 第 8 节，**不新增组件、不做 DOM 分支**（只在 `index.js` 给评论区和分享条补了 `j-comments`/`j-share` 两个类名作为隐藏锚点）。

### 材质清单

| 屏幕上的材质 | 纸上的处理 |
|---|---|
| 牛皮纸底 / 纸条底 | token 覆写成 `#ffffff`，正文墨色 `#1a1a1a` |
| 硬阴影 `--shadow` | `none` |
| 胶带、图钉、纸齿（`::before/::after`） | `display: none`——底色不印，留着只是空白占位 |
| 歪斜墨框（`border`） | **保留**，收到 1.5px；它是主题在纸上唯一的签名 |
| 邮戳、铅笔虚线、订书钉 | **保留**（本来就是线） |
| 纸条旋转 `rotate(±1.5deg)` | `transform: none`——跨页时带 transform 的盒子会成整体图元，切页处直接丢一整张纸 |
| 「纸会老」褪色档 | `--j-edge` 强制回墨色、日期戳 `opacity: 1`；打印件不该自带褪色 |
| 顶栏/页脚/进度/目录/分享/评论/上下篇/表单/复制按钮 | `display: none` |

### 版心与分页

- `@page { margin: 16mm }`，**不写 `size`**：写死 A4 会让 Letter 纸和用户"另存为 PDF"里自定义的尺寸一起失效
- **字号一律不动**。17px 落在 A4 上就是 12.75pt，手写标题 28–34px 是 21–25pt，本来就在合理区间；而 `#theme-journal .j-hand` 的特异度会压掉组件上的 Tailwind 绝对值（`text-[28px]`），为打印重设字号等于全站字号失控
- 打印不做多栏：`.j-shell`/`.j-day-spread`/`.j-days` 全改单列，中缝 `.j-spine` 撤掉
- `break-inside: avoid` 给纸条/便利贴/拍立得；`break-after: avoid` 给标题与引用——标题落在页尾是打印最常见的坏形

### 三处「声明生效了、设计却不成立」的坑

1. **深色代码块的深色不在 `pre.notion-code` 上，在容器 `.code-toolbar` 上**（`public/css/prism-mac-style.css` 的 `background: rgba(27,28,32,.94)`）。只把 `pre` 写成 `background: transparent !important` 会让父层的黑**透出来**——计算样式全绿、截图仍然是一坨黑。必须连 `.code-toolbar`/`.collapse-panel-wrapper` 一起清掉底色、阴影、边框、圆角与 `backdrop-filter`，并把 `overflow: hidden` 改 `visible`（否则跨页代码被裁）。
2. **语法色收敛要抬特异度**。屏幕态写的是 `#theme-journal .notion-code .token.keyword`（1-3-0 + `!important`），打印态一条 `#theme-journal .notion-code .token` 只有 1-2-0，**压不住**（实测仍返回 4 种色）。借正文容器抬到 2-2-0：`#theme-journal #article-wrapper .notion-code .token { color: var(--ink) !important }`。用 `.token` 兜底而不是逐类列举，因为 prism-mac 的类名比主题用到的多，列举必定漏。
3. **`border-radius` 在屏幕态就已经是 0**：prism-mac 的 `pre.notion-code { border-radius: 0 !important }` 压掉了主题的歪斜圆角，而主题那条没写 `!important`。按"代码块按现状"的口径屏幕规格不动，只在打印态把歪斜框用 `!important` 要回来——**所以打印态与屏幕态在代码块圆角上有意不一致**，屏幕侧这笔债记在这里。

### 折叠代码块必须强制展开

`CODE_COLLAPSE` 开启后长代码块是 `.collapse-panel { max-height: 0; overflow: hidden }`，打印会**整段代码裁没**且纸上毫无提示。打印态 `max-height: none !important` + `overflow: visible`。折叠标题（语言名）**留着**——它是纸上的语言标签；旁边的箭头涂鸦和侧栏按钮隐藏。
当前站点该配置是关的（实测 `collapse` 命中 0），但它是站长可开的正式配置，所以规则先就位。

### 其余翻译

- **方格稿纸 → 真边框**：网格是 `background-image`，纸上印不出来；改 `background-image: none` + 单元格 `border: 1px var(--ink) !important`
- **荧光笔 → 蓝圆珠笔双下划线**：`linear-gradient` 同理消失；`text-decoration: underline double` + `--blue`，"在纸上划两道"本来就是笔的语法
- **外链带出地址**：`#article-wrapper a[href^='http']::after { content: ' ' attr(href) }`，用 stamp 字体 9pt。**只在正文生效**——标签胶囊/返回/引用条里都是站内路径，展开只会脏；锚点 `href*='#'`、`notion-page-link`、`notion-bookmark` 显式 `content: none`
- **夜间态强制回浅**：token 覆写同时命中 `#theme-journal.j-night`，牛皮纸底不会跟着印成整页灰
- **加密页不需要专门处理**：口令输入框与"提交"都是 `background` 撑出来的，默认不印背景 → 纸上本来就只剩那行说明文字，自解释

### 不做

不做打印专用组件、不做 DOM 分支、不加"打印"按钮、不用 `@page` 页眉页脚、不做封面页。

### 验收方式

`page.emulateMediaType('print')` + 视口 **673×950**（A4 减 16mm 页边 ≈178mm @96dpi，用真实打印宽度才能把 `md:`/`lg:` 断点一起验到），再 `page.pdf({ format: 'A4', printBackground: false, margin: 16mm })` 对页数。
回归护栏在 `__tests__/themes/journalPrintStyles.test.js`（9 条，含上面三个坑与"不许出现 `print-color-adjust:`""字号只许 9pt"两条负向断言）。
## 同语言 OG 卡（D2 · 2026-10-10 落地，**已接线 · B 案**，接线口径见「接线决定」节）

**一句话规格**：分享卡是一张**贴在纸上的手账切片**——1200×630、纸底墨框、日期邮戳，把文章标题**按文章本身的语言原样**画进图片里。它是渲染产物而不是设计稿导出，所以本节的下半部分全是 `next/og` 的能力边界；审美上要跟手账语法一致，工艺上要跟 satori 一致，两者冲突时**工艺赢**（因为审美可以不调那一笔，工艺调不了）。

### 为什么要做：现状给爬虫的是假声明

- `components/SEO.js:182-184`：`og:image` 是 `meta.image || '/bg_image.jpg'`（`SEO.js:65`），而 `og:image:width/height` **写死 1200/630**。文章封面是 Notion 横图、`bg_image.jpg` 是站内旧背景图，两者都与 1200×630 无关 —— 尺寸在说谎，社交平台按假比例裁切就出现"封面被切一半"。
- 分享出去的视觉与 journal 的手账语法**零关系**：一张 Notion 封面 + 浏览器默认标题栏，认不出这是本站。

### 已实测的事实（规格依据，不是推测）

| 项 | 实测结果 | 对规格的影响 |
|---|---|---|
| 字体格式 | satori 对现有 `LXGWWenKai-Medium.subset.woff2` 报 `Unsupported OpenType signature wOF2`；WOFF / TTF 正常 | **不能复用任何 `.woff2` 资产**，必须另出字体件 |
| 字体体积 | 同一子集（7289 字）TTF 3,414,312 B → WOFF 2,109,888 B | 卡片字体是**第二份中文字体**，不是"把现有的换名" |
| 单卡耗时 | 3.4MB TTF 162ms / 2.11MB WOFF 120ms；同字体二次渲染 57ms | 进程内字体字节可复用，首次不免费 |
| 并发 | 30 并发总 1271ms，堆 17.8MB → 104.9MB | 线上机 V8 堆 1.9G，**在预算内**，但见下面红线 |
| 产出格式 | `contentType` 传 jpeg/webp 仍返回 `content-type: image/png`、魔数 `89504e47`、字节一致 | **只能 PNG**，别指望用 jpeg 压体积；单卡 31-36KB |
| CSS 能力 | 四值歪斜圆角、`radius-a/radius-b` 斜杠语法、`rotate`、无模糊硬阴影、线性渐变、荧光笔渐变、虚线框、单/双下划线 12 组 A/B 对比 md5 **全部互不相同且不同于对照** | journal 的签名属性在卡片上**都成立**，不需要为 satori 简化视觉语言 |

### 版式（1200×630）

沿用 MASTER 既有语法，不新增视觉元素：

- 纸底 `--paper #FDFBF7`、墨框 `--ink`、硬阴影 `5px 5px 0`（已实测可画）
- **三色只许出现一枚**，且必须带来源 —— 「状态编码」的规则延续到卡片上：随机装饰在网页上只是吵，在图片里会被读成"设计稿模板"
- 日期邮戳沿用「一天一摊」的 stamp 语法。⚠️ 拉丁字形（Amatic/Kalam/Cabin/JetBrains Mono）的自托管产物**也全是 WOFF2**，上卡同样要另出 WOFF/TTF；源 TTF 在子集化时已丢弃，需重新取
- **卡片不放正文摘要**：`meta.description` 是 SEO 句、不是手账语气，写上去只会像模板。卡面信息限于：站点名、标题、日期、状态标记（至多一枚）、类别
- 标题宽度是卡片唯一的硬风险：satori **没有文字测量 API**，截断只能按字符数估算，且中英文混排的字符数与视觉宽度关系不稳定 → 规格必须写"按字符数分档 + 最多 N 行 + 溢出省略号"，并把"标题超长"当成必验用例

### 路由与数据契约

- `pages/api/og.js`（Pages Router + Node runtime）。生产是 standalone SSR（Dockerfile `CMD ["node","server.js"]`），API 路由可用；仓库已有 `pages/api/{rss,revalidate,notion-comments}.js` 先例
- **运行期不取 Notion**：全部入参走 query（`?title=&date=&category=&state=&locale=`）。理由不是省时间，是**不让爬虫的抓取路径依赖 Notion API** —— Notion 限流或抖一下，分享卡就整片 500，而标题在 `getStaticProps` 阶段早就拿到了，没有理由不在服务端拼进 URL
- `Cache-Control: public, max-age=31536000, immutable` —— 参数在 URL 上，标题一改 URL 就变，**不需要失效策略**；这也是"运行期不取数据"的连带收益
- 字体加载一次进模块级变量（或 `globalThis`），实测同进程二次渲染 57ms 依赖的就是这一点
- 入参必须设上限并做转义（参数直接进 SVG/HTML 模板，标题里带 `<` 是可能的）

### 兜底（三条，缺一不可）

1. **route 抛错 / 字体缺失** → `og:image` 回落现状值 `meta.image || '/bg_image.jpg'`；SEO 组件不许因为卡片失败而整块不渲染
2. **`EXPORT=true` 的静态导出路会 404**：`next export` 不含 `pages/api`（`next.config.js:219/254/266/325` 都以 `process.env.EXPORT` 关掉动态能力为同证）。静态模式**不许**把 `og:image` 指向 `/api/og`，必须整体退回 1
3. **顺手修那条假声明**：走 OG 卡时才写 `og:image:width/height='1200'/'630'`（此时它是真的）；兜底时**省略**这两个 meta，而不是继续写死。注意这属共享组件 `components/SEO.js`，改它会波及所有主题 → 见待拍板第 4 条

### 「同语言」的确切含义

- 标题**原样**：不翻译、不转写。`og:locale` 已有正确来源（`SEO.js:71-73`：`router?.locale || LANG`，导出模式下 `router.locale` 为 undefined 时仍能回落），卡片只是不给它额外制造中英混排
- 卡面**固定 chrome 文字**（站点名、状态标）取本站语言字典（`lang/`），只有 `zh-CN`/`en-US` 两档；**不新建 i18n 面**
- 中文落 LXGW 子集、拉丁落自托管拉丁子集，两者都要 WOFF/TTF 版。⚠️ **卡片特有的新风险**：子集覆盖不到的字在网页上有 `font-display: swap` 兜底，在图片里就是**豆腐块**，且发出去之后无法补救（PNG 已经缓存）。→ 规格要求卡片字体至少覆盖 GB2312 一级，验收必须真渲一篇含生僻字的标题，而不是只看"能出图"

### 性能红线（对着线上机 2 核 / 1.9G 写的）

- **不许**把文章封面图取回来合成进卡片 —— 大图解码才是堆的杀手，中文字体一次 100MB 量级是可控的，封面图不是
- 卡片必须**无状态**（除字体缓存），不再叠一层 LRU：字体已经常驻，再缓存 PNG 只会把堆压力变成不可预测
- 单卡 PNG 实测 74-117KB（含稿纸格纹与整幅白纸条）可接受；不为体积牺牲视觉（PNG 无选项）

### 拍板结果（2026-10-10，四条已定）

1. **卡片字体格式 = WOFF**（2.11MB；TTF 3.41MB 落选，WOFF 更小且实测更快）
2. **卡面标题走 Print 层（印刷体）**，不走 Hand 层 —— 稳、不会因缺字出豆腐块
3. **状态标记上卡**（至多一枚，三色规则延续：必须有来源，不许随机装饰）
4. **不动 `components/SEO.js`** —— 假声明 `og:image:width/height` 保持原样

**⚠️ 第 4 条的连带后果（查证过，不是猜测）**：全站只有 `components/SEO.js` 决定 `og:image` —— `SEO` 组件在 `pages/_app.js:90` 渲染一次，图取 `getSEOMeta()` 里那段 `switch (router.route)` 的 `siteInfo?.pageCover` / 各 route 分支（`SEO.js:381+`），再落到 `image = getAbsoluteImageUrl(meta.image || '/bg_image.jpg', LINK)`（`SEO.js:65`）。**主题侧没有任何 head 注入点**（仓库里不存在 `_head.js`/`CUSTOM_HEAD` 之类的钩子），所以「不动 SEO.js」= 卡片渲染得出来但**没有任何页面会引用它**。
可行的三条路，实现时必须选一条并记在这里：
- **A 只做路由**：卡片靠直接 URL 使用（手动分享/未来的 OG 预览页），`og:image` 保持现状
- **B 主题内加第二枚 `og:image`**（`next/head` 不去重，会与 SEO.js 那枚**并存**）：谁生效取决于 parser，且 HTML 里出现两枚同名 property 是脏状态 —— **要先在真实渲染里量出先后顺序才可选**
- **C 只改 SEO.js 的那一行**（把 `image` 的来源开一个配置口子）：最小、可回滚，但违背第 4 条

**⚠️ 第 2 条的连带成本（Print 层今天没有任何本地资产）**：手写层有中文字体（`LXGWWenKai-Medium.subset.woff2`），Print 层的中文 `'Noto Sans SC'` **完全来自 Notion 设置项 `FONT_URL` 的 CDN**，仓库里一个字节都没有；拉丁 Print 层 Cabin 也只有 WOFF2（satori 不吃）。所以选 Print 层要多造两件 WOFF 资产：
- `public/fonts/NotoSansSC-Regular-OG.woff`（从 google/fonts 的 `NotoSansSC[wght].ttf` 用 varLib.instancer 取 400 档，再按 LXGW 同一字符集子集化）
- `public/fonts/Cabin-Regular-OG.woff` / `Cabin-SemiBold-OG.woff`（由现有 woff2 反解再封 WOFF）

顺带的收益值得记下：中文无衬线一旦自托管，**网页侧的 Print 层也能脱离 `FONT_URL`** —— 那笔唯一剩下的配置债就有了代码侧的退路（Noto SC 全量 CDN 会展开十几个 gstatic 分片，是比拉丁迁移更大的一笔流量）。但**这是另一件事，不并入 D2**。

### 接线决定（2026-10-10 拍板：**B 案** · 主题内第二枚 `og:image`）

不动 `components/SEO.js` 的前提下，用户在三选一里点了 **B**：journal 的 `LayoutSlug`（未锁定分支）用 `next/head` 注入一枚绝对 URL 的 `og:image`，参数即 `/api/og` 的 query 契约（`title/date/category/state/locale`；`site` 不传，由路由默认成 `BLOG.LINK` 的 host）。

- `state` 直接复用「状态编码」的 `stateMarks(post)` 键序（至多 3 个，卡面只画首枚）——**语法同源，卡片与页面不许有两套状态规则**
- **先修正一处本文此前写错的事实**：「B 案 · `next/head` 不去重」只对了一半。`next/head` 的 meta 确实按 `property`/`name`/`charSet`/`httpEquiv` 归一化身份，但**比较键是 `tag + 身份 + content` 三元组**——所以两枚 `property='og:image'` 但 content 不同的 meta **不会互相顶掉，SSR 与水合后都并存**（2026-10-10 实测，见「接线落地记录」）。哪枚生效交给 parser，本文下方那条「要先在真实渲染里量出先后顺序才可选」的门槛已由实测解除，量测结果就记在那里
- **兜底**（延续上文「兜底」第 1/2 条）：`EXPORT=true` 一律不注入（静态导出没有 `pages/api`），`og:image` 自然落回 SEO.js 的现状值。锁定文章**照常注入**——注入点在 `LayoutSlug` 的非空分支而非 `lock` 分支，而 `lock` 时 SEO.js 的 `og:title` 本来就带出标题，卡片不构成新的泄露（见落地记录第 3 条）
- 开关 `JOURNAL_OG_CARD`（默认 true）；接线改动只落在 `themes/journal/` 内，共享组件零改动
- 落地记录（实测结果）见本节末「接线落地记录」

### 原待拍板（已由上面取代，保留问题本身便于回看）

1. **卡片字体格式：WOFF（2.11MB）还是 TTF（3.41MB）？** 两者 satori 都吃；WOFF 小 38%、实测还略快（120ms vs 162ms），倾向 **WOFF**

### 落地记录（2026-10-10）

产物：`themes/journal/og-card.js`（卡面组件）+ `pages/api/og.js`（路由）+ 四件 WOFF 资产（`NotoSansSC-SemiBold` 1.43MB、`Cabin-Regular`/`Cabin-SemiBold` 各 24-25KB、`JetBrainsMono-Medium` 29KB，共 1.51MB）+ `OFL-NotoSansSC.txt` + 护栏 `__tests__/themes/journalOgCard.test.js`（9 条）。
**接线状态：未接**。按拍板第 4 条不动 `components/SEO.js`，所以走的是「A 只做路由」—— 卡片靠直接 URL 使用，`og:image` 保持现状。

**最值钱的一条：satori 的 display 规则比它的报错文案严格得多。**
报错写的是「more than one child node」，实际**一个 `<svg>` 子节点就会抛** —— `Pin`、`Fold`、手绘横线三个包着 svg 的 div 全部中招。而报错信息里**不含是哪个元素**，读代码也读不出来。有效的定位法是把组件当纯函数调用（`OgCard(props)` 直接拿到元素树），取出纸条的 children 逐个单独渲染做二分，一次就能指到具体节点。**推论：卡面树里每一个包着元素的 div 都要显式写 `display`，别指望"只有一个孩子"能免检。**

其它实测口径（草案里没有的）：

- `display: inline-block` 直接抛错，允许值只有 `flex | block | none | -webkit-box`
- **可以画**：`clip-path: polygon()`（和纸胶带锯齿）、内联 `<svg>`（`ellipse` + `strokeDasharray` 画邮戳双环）、`data:image/svg+xml` 背景（撕线墨点）、`repeating-linear-gradient`（稿纸格）
- **不能画**：`filter` / `feTurbulence` —— 网页的纸纹靠 SVG 湍流滤镜，卡片上不存在，所以卡面的地子换成**稿纸格纹**（`--grid` 同色，横竖各 32px 一道）。这是卡面对网页的一次**有意偏离**，不是降级
- 卡面**只出一档字重 600**：卡片没有正文，全是 display 与标签，为 400 再养一份 1.4MB 资产不值。中文 Print 层此前**本地零资产**（`'Noto Sans SC'` 完全来自 Notion 的 `FONT_URL` CDN），所以这份是从 `google/fonts` 的 `NotoSansSC[wght].ttf` 用 `varLib.instancer` 取 600 档再子集化来的
- 四件卡片资产的字符集**与手写层完全同一份 7289 码位**（从已上线的 `LXGWWenKai-Medium.subset.woff2` 反读 cmap），保证两族覆盖一致；生成命令：`pyftsubset --text-file=<同一码位> --flavor=woff --name-IDs=0,1,2,3,13,14 --layout-features=*`，拉丁那三件由现有 woff2 `flavor=None` 反解再封 WOFF
- **邮戳位置改判**：草案放右上，实现时撞开 —— 右上角是状态编码的地盘（加密折角 > 带图拍立得，MASTER 写死的一格），邮戳压上去两者重叠。定版：**邮戳在右下**（`bottom:14; right:58`，正好压在硬阴影上，像信封上的销票戳），右上角永远留给状态标
- **日期只写一遍**：邮戳已含 `MM.DD` + 年 + 星期，页脚再排一次 `2024-06-01` 是重复 —— 与「一天一摊」里 `hideDate` 同源的那条教训
- **同语言的实证**：`locale=en-US` 时 chrome 全英文（`JS King` / `Frontend` / `Photo` / `Sat`）、标题仍是原样中文。这就是「同语言」在卡面上的确切含义
- **护栏的反证**：把 `STATE_LABELS` 里的 `pinned` 改名 → 「state vocabulary does not drift」立刻变红，证明它真的在盯网页端 `stateMarks` 与卡面词表的同步
- **jest 里渲染不了 satori**：`ImageResponse` 内部走 dynamic import，jest 的 vm 会抛 `A dynamic import callback was invoked without --experimental-vm-modules`。所以护栏只能是**源码级静态断言**，像素验收必须走 dev server（或本地 babel 直挂组件的临时脚本）

### 接线落地记录（2026-10-10，B 案）

改动只落在 `themes/journal/`：`index.js` 的 `ogImageUrl(post, locale)` + `LayoutSlug` 未锁定分支的 `<Head>` 注入，`config.js` 新增 `JOURNAL_OG_CARD`（默认 true）。共享组件零改动，护栏在 `__tests__/themes/journalOgCard.test.js`（+2 条，共 11 条，已拿 HEAD 版反证这两条会红）。

**四条只有量过才知道的事实**：

- **并存，不覆盖**：SSR HTML 与水合后的真实 DOM 里 `og:image` 都是**两枚**（SEO.js 的现状值在前、卡片 URL 在后，均带 `data-next-head`）。去重键含 content，所以「后挂载者生效」这个 `next/head` 常规经验在**同 property 不同 content** 时不成立 —— 它是追加，不是替换
- **生效哪枚由 parser 决定**：取第一个的爬虫（微博等）拿到的是旧封面，取最后一个的或按 ogp.me 当图集处理（Telegram 会取多枚）的拿到卡片。微信/微博对**无图**页面按标题+描述兜底。口径「覆盖品牌图」在 parser 层**不保证**，真实分享效果要到线上发一条才知道 —— 这是 B 案接受的代价，C 案（改 SEO.js 一行）才能根除
- **锁定文章也注入**：`lock` 分支只是渲染 `ArticleLock`，SEO.js 的 `og:title` 本来就带锁定文章的标题，卡片只是把这枚已公开的标题画成图，不构成新的泄露。规格定为**接受**，不为此加例外。实测补充：密码校验在客户端（localStorage），所以 **SSR 阶段加密文章走的是未锁定分支**，注入照常发生 —— 上面那条「接受」不只是例外处理，而是加密文章的必然形态
- **页面级只有一份主题 `<Head>`**（`LayoutBase` 的字体 preload），所以不存在"两个 Head 互相看不见"的问题；但 `<Head>` 只许放在**无条件 return 之后**，且 `useRouter()` 必须提到 `LayoutSlug` 顶部的 early-return 之前（rules of hooks）

**实测样本**：`/article/adb-install` 注入 URL 为 `?title=…&date=2024-06-05&category=…&state=revised%2Cphoto&locale=zh-CN`（`state` 直接复用 `stateMarks` 的键序，卡片与页面同一套语法得证）；首页与归档仍是一枚现状值；`/api/og` 于本地 dev 返回 200 + `89504e47` + 91KB。

**dev 量测的两条假阴性（各浪费了一轮排查，判据记在这）**：
- **冷启动首响应不带主题 `<Head>` 内容**：重启后第 1~2 次请求某路由，`NOTION_CONFIG` 还没进全局快照，`siteConfig('LINK')` 落到 `blog.config` 的 localhost 默认值 → 非绝对 URL 守卫返回 null，HTML 里**连 SEO.js 那枚 og:image 都可能整块缺席**。同一路由连请求三次、只信第 3 次的计数
- **改主题代码后旧进程不认**：`next dev` 对 `themes/**` 的服务端模块缓存会以 `file -> memory HIT 100%` 的名义继续发旧 HTML，探针 meta 加上去也查无此串。唯一的判据是**换一个从没请求过的文章路由**（或重启后先 warm-up），而不是等更久或反复刷同一篇

- 形态按规格：红字手写「分享」+ 纯文字链接，链接直接复用 `a` 的蓝圆珠笔波浪下划线，不加任何图标
- 服务集走 `JOURNAL_SHARE_SERVICES`，默认 `link,weibo,twitter,email`；`link` 渲染成 `<button class="j-textlink">`（不是 `<a>` 也要有同一条波浪线，所以新增了 `.j-textlink`）
- 仍然尊重站点的 `POST_SHARE_BAR_ENABLE` 和 `post.type === 'Post'` 判定，站长不用改两处开关
- 除「复制」外的四项都渲染成真实 `<a href>`（服务端就用 `LINK + asPath` 兜底），所以禁用 JS 也点得动，符合性能红线里"静态导出下无 JS 也必须完整可读"

### 波浪下划线成了一个 token

`--hand-underline` 现在是那条蓝圆珠笔波浪线的唯一来源，`a` 与 `.j-textlink` 共用。因为它是内联 SVG、颜色写死在 data URI 里，`j-night` 必须再覆盖一次（夜间换成 `#7EA4D0`），否则牛皮纸上文字是亮蓝、下划线还是白天的深蓝。

## 反模式（Do NOT）

- ❌ 渐变、`backdrop-filter`、任何模糊阴影 —— 一旦出现就退回"模板感"
- ❌ 圆角现代卡片（`border-radius: 12px` 之类）
- ❌ 手写体排正文
- ❌ 第四种彩色
- ❌ 用 emoji 当图标
- ❌ JS 运行时随机旋转（SSR/CSR 不一致）
- ❌ 把整站做成真正的"纸张照片"——它是网页，不是扫描件
